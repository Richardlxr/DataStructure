## 1. 这章到底在解决什么问题？

数据结构课里的“外部查找”，重点不是普通内存里的查找，而是：

**数据量太大，主要放在外存里，比如磁盘、SSD、数据库文件。**

外存访问比内存慢很多，所以外部查找算法最关心：

```text
如何减少访问外存的次数？
```

而不是单纯减少 CPU 比较次数。

---

## 2. 主存储器与外存储器

| 类型   | 例子         | 特点        |
| ---- | ---------- | --------- |
| 主存储器 | 内存 RAM     | 快、小、断电丢失  |
| 外存储器 | 硬盘、SSD、U 盘 | 慢、大、可长期保存 |

外存不是一条记录一条记录地读，而是通常以“块”为单位读写。

比如一个磁盘块大小是 `8192` 字节，即使只想找其中一个整数，也可能要把整个块读进内存缓冲区。

所以外部查找的代价模型可以理解为：

```text
主要成本 = 访问了多少个磁盘块
次要成本 = 在内存里比较了多少次
```

一句话：

**内存里比较很快，访问外存很慢；外部查找的核心是少读磁盘块。**

---

## 3. 为什么普通二叉查找树不适合外部查找？

普通二叉查找树每个结点最多只有两个孩子：

```text
        50
       /  \
     30    70
    / \    / \
  20  40  60  80
```

如果整棵树存在外存里，那么访问一个结点就可能意味着读一次磁盘块。

查找路径越长，磁盘访问次数越多。

### 3.1 最坏情况

二叉查找树可能退化成链表：

```text
1
 \
  2
   \
    3
     \
      ...
```

如果有 `10,000,000` 条记录，最坏可能需要：

```text
10,000,000 次磁盘访问
```

假设 1 秒只能进行 6 次磁盘访问：

```text
10,000,000 / 6 ≈ 1,666,666.7 秒
≈ 463 小时
≈ 19 天
```

这完全不能接受。

### 3.2 平均情况

PPT 中提到：

```text
一次成功查找平均需要约 1.38 log N 次磁盘访问
```

当 `N = 10,000,000` 时：

```text
log2(10,000,000) ≈ 23.25
1.38 * 23.25 ≈ 32
```

也就是说，普通二叉查找树平均查一次可能要访问约 `32` 次磁盘。

如果 1 秒 6 次磁盘访问：

```text
32 / 6 ≈ 5.3 秒
```

一次查询 5 秒多，也不适合数据库或文件系统。

## 4. B 树的核心思想

B 树的目标：

**把树变得矮胖，减少树高，从而减少磁盘访问次数。**

普通二叉树：

```text
每个结点最多 2 个孩子
高度大约是 log2 N
```

B 树 / M 叉查找树：

```text
每个结点可以有很多个孩子
高度大约是 logM N
```

例如 `N = 10,000,000`。

如果是二叉树：

```text
log2(10,000,000) ≈ 23
```

如果是 100 叉树：

```text
log100(10,000,000) ≈ 3.5
```

也就是说，树高可以从二十多层降到四层左右。

所以一次查找可能只需要：

```text
读根结点
读第二层结点
读第三层结点
读叶子结点
```

大约 3 到 4 次磁盘访问。

## 5. B 树结点到底怎么组织？

核心理解：

```text
一个结点 = 一个有序 keys 数组 + 一个 child 指针数组
```

其中：

- `keys`：存关键字，也就是分界线。
- `child`：存孩子结点的位置，也就是通往不同区间的路。

### 5.1 一个具体例子

假设有这样一棵 B 树：

```text
              [25 | 40]
             /    |     \
      [10 | 13] [37 | 39] [52 | 54 | 55 | 71]
```

它在代码中的组织方式类似：

```cpp
root.keys = {25, 40};

root.child[0] -> keys = {10, 13};
root.child[1] -> keys = {37, 39};
root.child[2] -> keys = {52, 54, 55, 71};
```

根结点可以看成：

```text
root:
keys:   [25, 40]
child:  [ c0, c1, c2 ]
```

含义是：

```text
c0 里面的所有数 < 25
c1 里面的所有数在 25 和 40 之间
c2 里面的所有数 > 40
```

也可以画成：

```text
child[0]   keys[0]   child[1]   keys[1]   child[2]
   <25       25       25~40       40        >40
```

### 5.2 keys 和 child 的数量关系

如果一个结点有 `n` 个关键字，那么它最多有：

```text
n + 1 个孩子
```

例如：

```text
keys = [20, 40, 60]
```

那么孩子区间是：

```text
child[0]: 小于 20
child[1]: 20 到 40 之间
child[2]: 40 到 60 之间
child[3]: 大于 60
```

## 6. B 树查找过程

查找 `39`：

```text
当前结点：[25 | 40]
```

比较后发现：

```text
25 < 39 < 40
```

所以走中间孩子：

```text
child[1] -> [37 | 39]
```

然后在 `[37 | 39]` 中找到 `39`。

查找路径：

```text
[25 | 40] -> [37 | 39]
```

只访问了 2 个结点。

如果一个结点刚好对应一个磁盘块，那么这次查找大约就是 2 次块访问。

---

## 7. 叶子结点和非叶子结点

非叶子结点有孩子：

```cpp
keys  = {25, 40}
child = {左孩子, 中孩子, 右孩子}
```

叶子结点没有孩子：

```cpp
keys  = {10, 13}
child = {}
```

所以判断一个结点是不是叶子，通常需要一个标记：

```cpp
bool leaf;
```

## 8. 更贴近 PPT 的外存表示

PPT 中 B 树结点的信息形式可以理解成：

```text
A0, (K1, R1), A1, (K2, R2), A2, ..., (Kn, Rn), An
```

其中：

- `K`：关键字 key，比如学号、ID。
- `R`：记录地址 record address，也就是这条数据真正存放在哪里。
- `A`：孩子地址 child address，也就是下一个结点在哪里。

在内存代码里，`A` 可以是指针：

```cpp
Node* child;
```

但在真实数据库或文件系统里，`A` 更可能是：

```text
磁盘块编号 / 页号 / 文件偏移量
```

例如：

```text
root:
keys       = [25, 40]
childBlock = [1024, 2048, 4096]
```

含义是：

```text
小于 25 的数据去磁盘块 1024 找
25 到 40 之间的数据去磁盘块 2048 找
大于 40 的数据去磁盘块 4096 找
```

这就是 B 树适合外存的原因：

**一个 B 树结点可以设计成一个磁盘块，读一次磁盘就能拿到很多关键字和很多分叉信息。**

## 9. 当前阶段要记住的核心句子

1. 外部查找最重要的是减少外存访问次数。
2. 普通二叉查找树太高，所以不适合外存。
3. B 树通过增加分叉数，让树变矮。
4. B 树结点不是一个数，而是一个有序数组。
5. `keys` 是分界线，`child` 是通往对应区间的路。
6. 如果一个结点有 `n` 个关键字，那么最多有 `n + 1` 个孩子。
7. 真实外存里，孩子指针通常不是内存地址，而是磁盘块号、页号或文件偏移量。

## 10. 小检查

如果一个 B 树结点：

```text
keys = [30, 50, 80]
```

那么查找 `65` 应该走哪个孩子？

区间划分：

```text
child[0]: < 30
child[1]: 30 ~ 50
child[2]: 50 ~ 80
child[3]: > 80
```

所以：

```text
65 应该走 child[2]
```
