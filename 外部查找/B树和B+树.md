## 1. 这章到底在解决什么问题？

数据结构课里的“外部查找”，重点不是普通内存里的查找，而是：

**数据量太大，主要放在外存里，比如磁盘、SSD、数据库文件。**

外存访问比内存慢很多，所以外部查找算法最关心：

```text
如何减少访问外存的次数？
```

而不是单纯减少 CPU 比较次数。

---

## 2. 主存储器与外存储器

| 类型   | 例子         | 特点        |
| ---- | ---------- | --------- |
| 主存储器 | 内存 RAM     | 快、小、断电丢失  |
| 外存储器 | 硬盘、SSD、U 盘 | 慢、大、可长期保存 |

外存不是一条记录一条记录地读，而是通常以“块”为单位读写。

比如一个磁盘块大小是 `8192` 字节，即使只想找其中一个整数，也可能要把整个块读进内存缓冲区。

所以外部查找的代价模型可以理解为：

```text
主要成本 = 访问了多少个磁盘块
次要成本 = 在内存里比较了多少次
```

一句话：

**内存里比较很快，访问外存很慢；外部查找的核心是少读磁盘块。**

---

## 3. 为什么普通二叉查找树不适合外部查找？

普通二叉查找树每个结点最多只有两个孩子：

```text
        50
       /  \
     30    70
    / \    / \
  20  40  60  80
```

如果整棵树存在外存里，那么访问一个结点就可能意味着读一次磁盘块。

查找路径越长，磁盘访问次数越多。

### 3.1 最坏情况

二叉查找树可能退化成链表：

```text
1
 \
  2
   \
    3
     \
      ...
```

如果有 `10,000,000` 条记录，最坏可能需要：

```text
10,000,000 次磁盘访问
```

假设 1 秒只能进行 6 次磁盘访问：

```text
10,000,000 / 6 ≈ 1,666,666.7 秒
≈ 463 小时
≈ 19 天
```

这完全不能接受。

### 3.2 平均情况

PPT 中提到：

```text
一次成功查找平均需要约 1.38 log N 次磁盘访问
```

当 `N = 10,000,000` 时：

```text
log2(10,000,000) ≈ 23.25
1.38 * 23.25 ≈ 32
```

也就是说，普通二叉查找树平均查一次可能要访问约 `32` 次磁盘。

如果 1 秒 6 次磁盘访问：

```text
32 / 6 ≈ 5.3 秒
```

一次查询 5 秒多，也不适合数据库或文件系统。

## 4. B 树的核心思想
先记住：**m 阶 B 树里的 `m`，指的是一个结点最多有 m 个孩子。**

比如 5 阶 B 树：

```text
最多 5 个孩子
最多 4 个关键字
```

因为：

```text
关键字数 = 孩子数 - 1
```

---

### 1. 一个结点内部怎么组织？

一个 B 树结点长这样：

```text
child[0], key[0], child[1], key[1], child[2], key[2], child[3]
```

如果：

```text
keys = [20, 40, 60]
```

那么它把数据分成 4 个区间：

```text
child[0]: < 20
child[1]: 20 ~ 40
child[2]: 40 ~ 60
child[3]: > 60
```

所以：

```text
有 3 个 key，就有 4 个 child
有 n 个 key，就有 n + 1 个 child
```

---

### 2. m 阶 B 树的核心规则

以 **m 阶 B 树** 为通用规则：

#### 规则 1：每个结点最多 m 个孩子

```text
最多孩子数 = m
最多关键字数 = m - 1
```

如果是 5 阶 B 树：

```text
最多孩子数 = 5
最多 key 数 = 4
```

---

#### 规则 2：除根结点外，结点不能太空

非根结点至少要有：

```text
ceil(m / 2) 个孩子
```

所以至少有：

```text
ceil(m / 2) - 1 个 key
```

如果是 5 阶 B 树：

```text
至少孩子数 = ceil(5 / 2) = 3
至少 key 数 = 3 - 1 = 2
```

所以 5 阶 B 树中，普通非根结点的 key 数范围是：

```text
2 ~ 4 个 key
```

孩子数范围是：

```text
3 ~ 5 个孩子
```

这就是代码里的：

```cpp
static constexpr int MIN_CHILDREN = (ORDER + 1) / 2;
static constexpr int MIN_KEYS = MIN_CHILDREN - 1;
```

当 `ORDER = 5`：

```text
MIN_CHILDREN = 3
MIN_KEYS = 2
```

---

#### 规则 3：根结点比较特殊

根结点可以少一点。

如果根不是叶子，它至少有：

```text
2 个孩子
1 个 key
```

比如：

```text
      [40]
     /    \
[10 20]  [50 60]
```

这是合法的。

但普通非根结点如果只有 `[40]` 一个 key，在 5 阶 B 树里一般不合法，因为非根至少要 2 个 key。

---

#### 规则 4：所有叶子在同一层

B 树必须平衡。

不允许这样：

```text
        [40]
       /    \
    [20]    [60]
    /
 [10]
```

因为左边更深，右边更浅。

合法 B 树应该所有查找路径长度差不多，所有叶子在同一层。

这就是为什么 B 树查找稳定，不会退化成链表。

---

#### 规则 5：结点内部 keys 必须有序

比如：

```text
[10, 25, 40]
```

合法。

```text
[25, 10, 40]
```

不合法。

因为查找时要根据 key 判断走哪个 child。

---

### 3. 用 5 阶 B 树完整举例

这是一棵合法的 5 阶 B 树：

```text
              [25 | 40]
             /    |     \
      [10 | 13] [31 | 37] [52 | 55 | 71]
```

根结点：

```text
keys = [25, 40]
child 有 3 个
```

根可以有 2 个 key，合法。

下面三个叶子结点：

```text
[10 | 13]       有 2 个 key
[31 | 37]       有 2 个 key
[52 | 55 | 71]  有 3 个 key
```

对于 5 阶 B 树，非根结点 key 数要在：

```text
2 ~ 4
```

所以都合法。

---

### 4. 不合法例子

#### 例子 1：结点太满

```text
[10 | 20 | 30 | 40 | 50]
```

这是 5 个 key。

5 阶 B 树最多只能有：

```text
4 个 key
```

所以不合法，要分裂。

---

#### 例子 2：非根结点太空

```text
        [40]
       /    \
    [10]   [50 | 60]
```

如果这是 5 阶 B 树，那么 `[10]` 这个非根结点只有 1 个 key。

但非根结点至少要：

```text
2 个 key
```

所以不合法。

删除时如果删成这样，就要借位或者合并。

---

### 5. 你现在最该记住的版本

对于 **5 阶 B 树**：

```text
每个结点最多 5 个孩子
每个结点最多 4 个 key

除根外：
每个结点至少 3 个孩子
每个结点至少 2 个 key

根特殊：
根可以只有 1 个 key
如果整棵树为空，根也可以没有 key

所有叶子必须在同一层
每个结点内部 keys 必须有序
```

一句话总结：

**B 树靠“最多不能太满、最少不能太空、所有叶子同层”来保持矮胖和平衡。**
