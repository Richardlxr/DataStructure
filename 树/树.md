### 第一阶段：树与二叉树的基本概念与性质

#### 1. 树（Tree）的本质与定义

树是一种典型的非线性数据结构，它可以非常自然地用来进行问题建模 。

- **数学定义**：树是 $n$（$n \ge 1$）个结点的有限集合 $T$ 。
    
- **结构特征**：
    
    1. 必定存在唯一一个被称为**根（root）**的结点 。
        
    2. 当 $n > 1$ 时，其余结点可分为 $m$（$m \ge 0$）个互不相交的集合 $T_1, T_2, \dots, T_m$ 。
        
    3. 这些集合本身也是一棵树，被称为根结点的**子树（Subtree）**，这体现了树结构在物理内存上的**递归性质** 。
        

#### 2. 核心专业术语

在进行算法推导时，必须清晰界定以下术语：

- **结点的分类**：包含根结点、内部节点以及度为 0 的叶结点（树叶） 。
    
- **结点的度与树的度**：结点的度是指其拥有的子树数量；树的度是所有结点中度的最大值 。
    
- **结点间的关系**：父亲结点、儿子结点、兄弟结点、祖先结点与子孙结点 。
    
- **树的层次**：结点的深度（从根向下）、树的高度（从叶向上计算的最大层数） 。
    

#### 3. 二叉树（Binary Tree）与一般树的区别

二叉树经常被误解为“普通的树”。在严格的计算机科学定义中：

- **定义**：二叉树是结点的有限集合，它可以是**空集**，或者由一个根结点及左、右子树构成，且左右子树本身也是二叉树并互不相交 。
    
- **关键差异**：
    
    1. 二叉树**严格区分左、右子树**，次序不能颠倒 。
        
    2. 二叉树可以为空，但一般的树不能为空（$n \ge 1$） 。
        
    3. 二叉树**不是**特殊的一般树，二叉树和有序树是不同的概念 。
        ![[截屏2026-03-24 上午9.21.34.png]]

#### 4. 特殊形态的二叉树

这两种特殊的二叉树在内存分配（尤其是连续内存/数组存储）中具有重要意义：

- **满二叉树**：一棵高度为 $k$ 且具有 $2^k-1$ 个结点的二叉树。其任意一层的结点个数都达到了理论最大值 。
    
- **完全二叉树**：在满二叉树的最底层，自右至左依次去掉若干个结点而形成的树。其所有的叶结点必定且只出现在最低的两层上 。
    ![[截屏2026-03-24 上午9.24.41.png]]

#### 5. 二叉树的四大核心数学性质

在分析算法的时间与空间复杂度时，这些公式是重要依据：

- **性质 1**：一棵非空二叉树的第 $i$ 层上最多有 $2^{i-1}$ 个结点（$i \ge 1$） 。
    
- **性质 2**：一棵高度为 $k$ 的二叉树最多具有 $2^k-1$ 个结点 。
    
- ==**性质 3**：对于一棵非空二叉树，如果叶子结点数为 $n_0$，度数为 2 的结点数为 $n_2$，则恒有：$n_0 = n_2 + 1$ 成立 。(推导基础：边数 $B = n - 1$，且 $B = n_1 + 2n_2$ )。==
    
- ==**性质 4**：具有 $n$ 个结点的完全二叉树的高度 $k = \lfloor \log_2 n \rfloor + 1$ 。==

> [!info] ### 三种遍历+拓展
>

#### 1. 前序遍历 (Pre-order)

**执行规则**：先执行当前结点的任务，再去处理左侧，最后处理右侧 。


#### 2. 中序遍历 (In-order)

**执行规则**：先必须处理完左侧的所有任务，然后才能执行当前结点的任务，最后处理右侧。



#### 3. 后序遍历 (Post-order)

**执行规则**：左侧和右侧的任务都必须彻底完成，最后才能执行当前结点的任务。

```cpp
    struct StNode {
        Node < T > * node;
        int poptimes;
        StNode(Node < T > * n = nullptr): node(n), poptimes(0) {}
    };
    //状态机！！！！记录被弹出的次数，如果2次说明左边处理完了，先访问自己，再访问右边
    void NonRecursion_In() {
        if (root == nullptr)
            return;

        std::stack < StNode > s; // 栈里直接存放包装好的状态对象
        s.push(StNode(root));

        std::cout << "非递归中序遍历: ";

        while (!s.empty()) {
            StNode current = s.top(); // 1. 值拷贝获取栈顶元素（安全）
            s.pop(); // 2. 弹出栈顶元素

            current.poptimes += 1; // 3. 状态推进

            if (current.poptimes == 2) {
                // 状态 2：左边已经处理完了。
                // 动作：访问自己，然后把右孩子加进计划表。绝不把自己再加回去！
                std::cout << current.node - > data << ' ';
                if (current.node - > right) {
                    s.push(StNode(current.node - > right));
                }
            } else {
                // 状态 1：第一次碰到它。
                // 动作：自己还没处理完，压回去。然后把左孩子加进计划表（左孩子后进先出，优先处理）。
                s.push(current);
                if (current.node - > left) {
                    s.push(StNode(current.node - > left));
                }
            }
        }
        std::cout << std::endl;
    }
```

#### 前+中遍历序列推树


- **前序遍历与中序遍历结合构造**：
    
    - **前序序列的宏观特征**：序列的第一个元素必然是当前二叉树（或子树）的**根结点** 。
        
    - **中序序列的宏观特征**：在中序序列中定位到该根结点后，其左侧的所有元素构成**左子树**的集合，其右侧的所有元素构成**右子树**的集合 。
        
    - **算法流程（分治法）**：提取前序序列首元素作为根 $\rightarrow$ 在中序序列中查找到该根的位置 $\rightarrow$ 计算出左、右子树的结点数量（即区间长度） $\rightarrow$ 依据长度在前序和中序序列中划分出左、右子树的子区间 $\rightarrow$ 递归地对左右子区间执行上述操作。
	- ==**递归思想是想求出这颗树，只需要去求左右子树就可以了；分而治之**==
	- 我们的做法就是：==**先拿出前序序列每个区间里面的root，然后去给定的中序区间去找；得到左右子树的元素总个数-->得到了新的左右前序区间**==（去感受一下第五步）
        
- **后序遍历与中序遍历结合构造**：
    
    - **后序序列的宏观特征**：序列的**最后一个元素**必然是当前二叉树（或子树）的根结点 。
        
    - **算法流程**：逻辑与前序结合法高度一致。区别仅在于提取根结点的位置从前序的首端变更为了后序的末端。提取后，同样利用该元素去中序序列中划分左、右子树集合，进而递归构建 。
        
- **注意**：前序序列与后序序列的组合通常无法唯一确定二叉树（当树中存在只有一个孩子的内部结点时会产生拓扑歧义）。


```cpp
Node < T > * buildFromPreInRecursive(const std::vector < T > & pre, int preStart, int preEnd,
    const std::vector < T > & in, int inStart, int inEnd) {
    // 1. 基线条件：区间为空，返回空指针
    if (preStart > preEnd || inStart > inEnd) {
        return nullptr;
    }

    // 2. 提取根节点：前序序列的第一个元素
    Node < T > * root = new Node < T > (pre[preStart]);

    // 3. 在当前中序区间 [inStart, inEnd] 内寻找根节点的位置
    int index = inStart;
    while (index <= inEnd && in [index] != pre[preStart]) {
        index++;
    }

    // 4. 计算左子树的元素个数（极其关键）
    int leftLength = index - inStart;

    // 5. 严格按照推导出的边界，递归构建左右子树
    root - > left =
        buildFromPreInRecursive(pre, preStart + 1, preStart + leftLength, // 左子树的前序区间
            in, inStart, index - 1 // 左子树的中序区间
        );

    root - > right =
        buildFromPreInRecursive(pre, preStart + leftLength + 1, preEnd, // 右子树的前序区间
            in, index + 1, inEnd // 右子树的中序区间
        );

    // 6. 返回建好的这棵子树的根
    return root;
}
```

#### 层次遍历（广度优先遍历）
#### 算法执行流

1. 若树非空，首先将根结点指针入队 。
    
2. 当队列不为空时，持续执行以下循环过程 ：
    
    - 将位于队首的结点指针出队，并访问（输出）该结点的数据 。
        
    - 检查刚出队的结点是否具有左孩子；若有，则将其左孩子指针入队 。
        
    - 检查刚出队的结点是否具有右孩子；若有，则将其右孩子指针入队 。
        

#### 队列状态对应图解

**假定二叉树结构如下：**

- 第一层：A
    
- 第二层：L（A的左孩子）, C（A的右孩子）
    
- 第三层：B, E（均为L的子结点）；D（C的子结点）
    
- 第四层：P, S（均为B的子结点）
    

**队列变化过程跟踪（左侧为队头，右侧为队尾）：**

|**步骤**|**当前出队结点**|**当前入队结点**|**队列内部状态 (队首 -> 队尾)**|
|---|---|---|---|
|1|无|A|`[A]`|
|2|A|L, C|`[L, C]`|
|3|L|B, E|`[C, B, E]`|
|4|C|D|`[B, E, D]`|
|5|B|P, S|`[E, D, P, S]`|
|6|E|无|`[D, P, S]`|
|7|D|无|`[P, S]`|
|8|P|无|`[S]`|
|9|S|无|`[]` (遍历结束)|

输出序列最终为：A, L, C, B, E, D, P, S。

```cpp
public:

        std::queue < Node < T > * > que; // 声明辅助队列
        que.push(root); // 根结点入队

            // 3. 访问该结点
            std::cout << temp - > data << ' ';

            // 4. 左右孩子依次入队
            if (temp - > left != nullptr) {
                que.push(temp - > left);
            }
            if (temp - > right != nullptr) {
                que.push(temp - > right);
            }
        }
```

### 哈夫曼编码核心知识点

#### 1. 为什么要用哈夫曼编码？
*   **背景**：计算机存储字符通常用等长编码（比如ASCII码，每个字符固定8位）。但实际英文文章中，'e' 出现的频率极高，而 'z' 很少出现。
*   **思想**：如果让出现**频率高**的字符编码**短**，出现**频率低**的字符编码**长**，是不是就能压缩整个文件的体积？
*   **应用**：ZIP压缩、JPEG图像压缩的核心算法之一。

#### 2. 什么是“前缀码”？
*   既然编码长度不一，解码时怎么知道哪几个01组合代表一个字符？
    *   *反例*：如果 A=0, B=1, C=01。当你收到 "01" 时，它是表示 "A+B" 还是 "C"？这就产生了**歧义**。
*   **前缀码规则**：**任何一个字符的编码，都不能是另一个字符编码的前缀。**
*   **哈夫曼树的巧妙之处**：在哈夫曼树中，所有实际字符都挂在**叶子节点**上。因为从根走到一个叶子节点，不可能路过另一个叶子节点，所以完美保证了“前缀码”的性质！

#### 3. 哈夫曼树（最优二叉树）的核心概念
*   **权重（Weight）**：字符出现的频率或次数。
*   **路径长度**：从根节点到该节点的边数。
*   **树的带权路径长度（WPL, Weighted Path Length）**：所有**叶子节点**的 （权重 × 路径长度）之和。
*   **定义**：给定 n 个权值，构造出一棵包含 n 个叶子节点的二叉树，**WPL最小的树就是哈夫曼树**。

#### 4. ==如何构造哈夫曼树？（贪心算法思想）==
*   **核心口诀：“挑最小、组CP、变新树、再循环”**
*   **步骤**：
    1.  把每一个带有权重的字符，当成一棵只有根节点的树，形成一个“森林”。
    2.  在森林里挑出**权重最小**的两棵树，作为左右子树，合并成一棵新树。新树根节点的权重 = 左右子树权重之和。
    3.  把那两棵被挑走的小树从森林中**删除**，把这棵**新树加入**森林。
    4.  重复步骤2和3，直到森林里**只剩下一棵树**。这棵树就是哈夫曼树！
*   *约定俗成（为了结果一致性）*：通常让左子树权重 $\le$ 右子树权重；向左走记为 '0'，向右走记为 '1'。

## 一般的树
### 1. 双亲表示法 (Parent Representation)

这种方法的核心思想是：**“只认爹，不认娃”**。

因为树中除了根节点外，每个节点都有且仅有一个父节点。我们可以利用一段连续的物理内存（数组）来存储所有的节点，并在每个节点中额外保存一个指向其父节点位置的索引（或者指针）。

**内存与性能特性：**

- **内存布局：** 连续内存分配。这种数组形式的布局具有极佳的 **Cache Locality（缓存局部性）**，CPU 在遍历节点时缓存命中率非常高。
    
- **时间复杂度：** 找父节点的时间复杂度是 $O(1)$。但如果想要找某个节点的所有孩子，就必须遍历整个数组，时间复杂度退化为 $O(n)$。
    

**C++ 结构示例：**

C++

```c
#define MAX_TREE_SIZE 100

template <typename T>
struct PTNode {
    T data;         // 节点数据
    int parent;     // 双亲位置索引（根节点的 parent 通常设为 -1）
};

template <typename T>
struct PTree {
    PTNode<T> nodes[MAX_TREE_SIZE]; // 连续内存数组
    int root;                       // 根节点的位置索引
    int node_num;                   // 当前树中的节点总数
};
```

---

### 2. 孩子链表示法 (Child Representation)

这种方法走向了另一个极端：**“只管娃，不管爹”**。

由于一个节点可以有多个孩子，且数量不确定，通常会采用“数组 + 链表”的混合内存模型。我们把树中的所有节点存放在一个数组中，同时为每个节点拉出一条单链表，这条链表里存储着该节点所有孩子在数组中的索引。

**内存与性能特性：**

- **内存布局：** 表头是连续数组，但孩子链表是动态分配的离散内存。这种结构存在较高的指针开销（Pointer Overhead），且链表的指针追逐（Pointer Chasing）容易导致 CPU 缓存未命中（Cache Miss）。
    
- **时间复杂度：** 找某个节点的所有孩子非常快，只需遍历其对应的链表即可。但如果想找某个节点的父节点，则需要遍历所有节点的链表，非常耗时。
    

**C++ 结构示例：**

C++

```c
// 孩子链表中的节点（只存索引和 next 指针）
struct CTNode {
    int child;          // 孩子节点在表头数组中的索引
    CTNode* next;       // 指向下一个孩子的指针
};

// 表头数组中的节点（存实际数据和链表头指针）
template <typename T>
struct CTBox {
    T data;             // 节点数据
    CTNode* first_child;// 指向第一个孩子的指针
};

template <typename T>
struct CTree {
    CTBox<T> nodes[MAX_TREE_SIZE]; // 节点数组
    int root;                      // 根节点索引
    int node_num;                  // 节点数量
};
```

---

### 3. 孩子兄弟链表示法 (Child-Sibling Representation)

又被称为**二叉链表表示法**，这是树结构中最优雅的一种表示方法。它的核心法则是：**“左指针指向大儿子，右指针指向亲兄弟”**。

无论一棵树原本有多么复杂（每个节点有任意多个分支），通过这种表示法，都可以将其在逻辑上**100% 转换为一棵标准的二叉树**。

**具体规则：**

1. **`first_child` (左指针)**：指向该节点的第一个孩子（长子）。
    
2. **`next_sibling` (右指针)**：指向该节点的右侧紧邻亲兄弟。
    

**内存与性能特性：**

- **内存布局：** 纯动态指针分配，节点结构完全统一，不存在由于节点度数不同而导致的空间浪费。这也是现代开发中最常用的泛型树内存布局方式。
    
- **工程价值：** 既然任何树都能转化为二叉树，那么我们就可以直接复用二叉树的各种高效算法（如递归遍历、非递归的栈模拟遍历等）来处理普通树，极大地降低了代码的复杂度和维护成本。
    

**C++ 结构示例：**

C++

```c
template < typename T >
    struct CSNode {
        T data; // 节点数据
        CSNode * first_child; // 左指针：指向第一个孩子
        CSNode * next_sibling; // 右指针：指向右侧相邻的亲兄弟
    };
```

### 总结对比

|**表示法**|**物理内存布局**|**找父节点效率**|**找子节点效率**|**核心应用场景**|
|---|---|---|---|---|
|**双亲表示法**|连续数组 (Cache 友好)|$O(1)$|$O(n)$|并查集 (Disjoint Set) 的底层实现。|
|**孩子链表示法**|数组 + 离散链表|极差|快|需要频繁遍历特定节点所有子树的场景。|
|**孩子兄弟表示法**|离散节点 (二叉树)|差 (除非加 parent 指针)|较快|树林与二叉树的相互转换、通用文件系统目录树。|
