### 第一阶段：树与二叉树的基本概念与性质

#### 1. 树（Tree）的本质与定义

树是一种典型的非线性数据结构，它可以非常自然地用来进行问题建模 。

- **数学定义**：树是 $n$（$n \ge 1$）个结点的有限集合 $T$ 。
    
- **结构特征**：
    
    1. 必定存在唯一一个被称为**根（root）**的结点 。
        
    2. 当 $n > 1$ 时，其余结点可分为 $m$（$m \ge 0$）个互不相交的集合 $T_1, T_2, \dots, T_m$ 。
        
    3. 这些集合本身也是一棵树，被称为根结点的**子树（Subtree）**，这体现了树结构在物理内存上的**递归性质** 。
        

#### 2. 核心专业术语

在进行算法推导时，必须清晰界定以下术语：

- **结点的分类**：包含根结点、内部节点以及度为 0 的叶结点（树叶） 。
    
- **结点的度与树的度**：结点的度是指其拥有的子树数量；树的度是所有结点中度的最大值 。
    
- **结点间的关系**：父亲结点、儿子结点、兄弟结点、祖先结点与子孙结点 。
    
- **树的层次**：结点的深度（从根向下）、树的高度（从叶向上计算的最大层数） 。
    

#### 3. 二叉树（Binary Tree）与一般树的区别

二叉树经常被误解为“普通的树”。在严格的计算机科学定义中：

- **定义**：二叉树是结点的有限集合，它可以是**空集**，或者由一个根结点及左、右子树构成，且左右子树本身也是二叉树并互不相交 。
    
- **关键差异**：
    
    1. 二叉树**严格区分左、右子树**，次序不能颠倒 。
        
    2. 二叉树可以为空，但一般的树不能为空（$n \ge 1$） 。
        
    3. 二叉树**不是**特殊的一般树，二叉树和有序树是不同的概念 。

#### 4. 特殊形态的二叉树

这两种特殊的二叉树在内存分配（尤其是连续内存/数组存储）中具有重要意义：

- **满二叉树**：一棵高度为 $k$ 且具有 $2^k-1$ 个结点的二叉树。其任意一层的结点个数都达到了理论最大值 。
    
- **完全二叉树**：在满二叉树的最底层，自右至左依次去掉若干个结点而形成的树。其所有的叶结点必定且只出现在最低的两层上 。

#### 5. 二叉树的四大核心数学性质

在分析算法的时间与空间复杂度时，这些公式是重要依据：

- **性质 1**：一棵非空二叉树的第 $i$ 层上最多有 $2^{i-1}$ 个结点（$i \ge 1$） 。
    
- **性质 2**：一棵高度为 $k$ 的二叉树最多具有 $2^k-1$ 个结点 。
    
- ==**性质 3**：对于一棵非空二叉树，如果叶子结点数为 $n_0$，度数为 2 的结点数为 $n_2$，则恒有：$n_0 = n_2 + 1$ 成立 。(推导基础：边数 $B = n - 1$，且 $B = n_1 + 2n_2$ )。==
    
- ==**性质 4**：具有 $n$ 个结点的完全二叉树的高度 $k = \lfloor \log_2 n \rfloor + 1$ 。==
    

---

#### 6.二叉树和二叉堆

| 特性       | 二叉树 (Binary Tree)       | 二叉堆 (Binary Heap)                   |
| -------- | ----------------------- | ----------------------------------- |
| **定义**   | 每个节点最多有两个孩子（左、右），没有额外限制 | 完全二叉树（Complete Binary Tree），且满足堆序性质 |
| **节点关系** | 左右子节点可任意排列              | 最大堆：父节点 ≥ 子节点；最小堆：父节点 ≤ 子节点         |
| **形状限制** | 没有限制，可**稀疏**、不平衡        | 必须是完全二叉树（除了最底层可能不满，从左向右填充）          |

# 存储容器

## 数组存储
### 1️⃣ 数组存储的原理

假设我们用数组 `A[0..n-1]` 存二叉树节点：

- 对于节点 `A[i]`：
    
    - 左子节点：`A[2*i + 1]`
        
    - 右子节点：`A[2*i + 2]`
        
    - 父节点：`A[(i-1)/2]` （取整）


> [!important] 核心重点
> **知识点**：`father=(son-1)>>1`
> 
>注意，这是索引从0开始的


这个索引计算公式 **要求树节点按层从上到下、从左到右连续排列**，这正是完全二叉树的特点。


- **完全二叉树 → 数组存储非常适合**（紧凑、高效）
    
- **非完全二叉树 → 数组存储可以，但浪费空间**，更常用链表存储

> [!info] ### 三种遍历+拓展
>

#### 1. 前序遍历 (Pre-order)

**执行规则**：先执行当前结点的任务，再去处理左侧，最后处理右侧 。


#### 2. 中序遍历 (In-order)

**执行规则**：先必须处理完左侧的所有任务，然后才能执行当前结点的任务，最后处理右侧。



#### 3. 后序遍历 (Post-order)

**执行规则**：左侧和右侧的任务都必须彻底完成，最后才能执行当前结点的任务。



```cpp
public:
    // 前序遍历公有接口
    void preOrder() const {
        std::cout << "前序遍历: ";
        preOrderRecursive(root);
        std::cout << std::endl;
    }

// 中序遍历公有接口
void inOrder() const {
    std::cout << "中序遍历: ";
    inOrderRecursive(root);
    std::cout << std::endl;
}

// 后序遍历公有接口
void postOrder() const {
    std::cout << "后序遍历: ";
    postOrderRecursive(root);
    std::cout << std::endl;
}

private:
    // 前序遍历递归逻辑
    void preOrderRecursive(Node < T > * node) const {
        if (node == nullptr) return; // 遇到空树，直接返回
        std::cout << node - > data << " "; // 1. 访问根结点
        preOrderRecursive(node - > left); // 2. 遍历左子树
        preOrderRecursive(node - > right); // 3. 遍历右子树
    }

// 中序遍历递归逻辑
void inOrderRecursive(Node < T > * node) const {
    if (node == nullptr) return;
    inOrderRecursive(node - > left); // 1. 遍历左子树
    std::cout << node - > data << " "; // 2. 访问根结点
    inOrderRecursive(node - > right); // 3. 遍历右子树
}

// 后序遍历递归逻辑
void postOrderRecursive(Node < T > * node) const {
    if (node == nullptr) return;
    postOrderRecursive(node - > left); // 1. 遍历左子树
    postOrderRecursive(node - > right); // 2. 遍历右子树
    std::cout << node - > data << " "; // 3. 访问根结点
}
```


### 第四阶段：哈夫曼树与哈夫曼编码（数据压缩的魔法）

#### 1. 为什么要学哈夫曼编码？（从等长到不等长）

在计算机中，每个字符都是用特定的二进制编码表示的 。大多数传统编码系统（如 ASCII）采用的是**等长编码** 。

假设我们有一段文本，里面只有 7 种字符，它们出现的频次（权重）分别是：$a(10)$、$e(15)$、$i(12)$、$s(3)$、$t(4)$、空格(13)、换行(1) 。

- 如果用**等长编码**，7 种字符至少需要 3 bit（因为 $2^2 < 7 < 2^3$）。总共占用的存储量就是：$3 \times (10+15+12+3+4+13+1) = 174$ bit 。
    
- **优化思路**：如果我们让出现频率高的字符（比如 $e$）编码短一点（比如就 2 bit），频率低的字符（比如换行）编码长一点，不就可以大大压缩总长度了吗 ？
    

#### 2. 核心难点：前缀编码（Prefix-Free Code）

如果采用不等长编码，会面临一个致命问题：**解码歧义**。假设 $e$ 是 `0`，$a$ 是 `01`，那么当你收到机器码 `01` 时，它到底是解成 `$e$ + 另一个代码` 还是解成 `$a$`？

为了让计算机能够唯一解码，必须满足一个铁律：==**任何一个字符的编码，都不能是另一个字符编码的前缀**== 。 在二叉树中，完美的解决方案是：**把需要编码的字符，全部放在叶结点上！** 规定左分支代表 `0`，右分支代表 `1` 。因为叶结点没有子结点，所以从根走到任何一个叶结点的路径（编码），绝对不可能是去其他叶结点路径的前缀。

#### 3. 构造魔法：哈夫曼算法（贪心思想）

那么，给定一堆字符和它们的频率，怎么构建出代价最小（总编码最短）的哈夫曼二叉树呢 ？讲义中给出了极其经典的“自底向上”算法 ：

1. **初始状态**：把所有 $n$ 个带有权值（频次）的字符，看作 $n$ 棵只有根结点的“孤树”集合 。
    
2. **合并（循环 $n-1$ 次）** ：
    
    - 从集合里挑出权值**最小**和**次小**的两棵树 。
        
    - 把这俩哥们儿变成一个新结点的左右儿子。新结点的权值，就是它俩的权值之和 。
        
    - 把原来的两棵树从集合里踢掉，把新结点塞回集合里 。
        
3. **结束**：随着树越并越少，最后集合里只剩下 1 个结点时，它就是整棵哈夫曼树的根 。
    

_(你看，权重越小的人越早被合并，就会被沉在树的最底层，路径最长；权重越高的人越晚被合并，离根就越近，路径越短！)_

#### 4. 存储技巧：静态链表（数组）

哈夫曼树有一个非常棒的数学性质：如果我们要编码 $n$ 个字符（即有 $n$ 个叶子结点），根据我们在第一阶段学的公式 $n_0 = n_2 + 1$，哈夫曼树中度数为 2 的结点有 $n-1$ 个，所以树的总大小严格等于 $2n - 1$ 。

因为大小完全固定，我们**不再需要用复杂的指针**去动态 `new` 内存！我们直接开辟一个大小为 $2n$ 的**连续数组**（为了方便，下标 0 通常不用，从 1 到 $2n-1$ 存储结点） 。数组里的每个元素记录自己的权值、父结点在哪、左孩子在哪、右孩子在哪 。
