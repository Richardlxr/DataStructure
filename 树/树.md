# 二叉树

## **二叉树不是特殊的树！！**
- ==二叉树严格区分左右子树（树不区分）；二叉树可以**为空，可以中间缺儿子只从另一个儿子延伸！**==

| 特性       | 二叉树 (Binary Tree)       | 二叉堆 (Binary Heap)                   |
| -------- | ----------------------- | ----------------------------------- |
| **定义**   | 每个节点最多有两个孩子（左、右），没有额外限制 | 完全二叉树（Complete Binary Tree），且满足堆序性质 |
| **节点关系** | 左右子节点可任意排列              | 最大堆：父节点 ≥ 子节点；最小堆：父节点 ≤ 子节点         |
| **形状限制** | 没有限制，可**稀疏**、不平衡        | 必须是完全二叉树（除了最底层可能不满，从左向右填充）          |

# 存储容器

### 1️⃣ 数组存储的原理

假设我们用数组 `A[0..n-1]` 存二叉树节点：

- 对于节点 `A[i]`：
    
    - 左子节点：`A[2*i + 1]`
        
    - 右子节点：`A[2*i + 2]`
        
    - 父节点：`A[(i-1)/2]` （取整）
        

这个索引计算公式 **要求树节点按层从上到下、从左到右连续排列**，这正是完全二叉树的特点。

---

### 2️⃣ 为什么完全二叉树最适合数组存储

- **没有“空洞”**：数组中的每个位置都存实际节点，节省空间。
    
- **索引运算简单**：直接通过上面的公式访问父子节点，不需要额外指针。
    
- **操作效率高**：上浮、下沉操作只需简单索引计算。
    

---

### 3️⃣ 非完全二叉树可以存数组吗？

- 可以，但会浪费很多空间，因为“空位置”也要占数组。
    
- 例子：一个只有左孩子或右孩子的稀疏二叉树，用数组存会出现很多空位。
    
- 这种情况下，通常 **用链式存储（节点指针）更合理**。
    

---

### ✅ 总结

- **完全二叉树 → 数组存储非常适合**（紧凑、高效）
    
- **非完全二叉树 → 数组存储可以，但浪费空间**，更常用链表存储
