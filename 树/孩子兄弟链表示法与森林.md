## 普通树先根遍历=\=二叉树先序遍历

- **普通树的先根顺序：** 父亲 $\rightarrow$ 大儿子 $\rightarrow$ 二儿子 $\rightarrow$ 三儿子...
    
- **二叉树的先序顺序：** 根 $\rightarrow$ 左子树 $\rightarrow$ 右子树。
    
- **对应关系：** 在二叉树中，访问“左子树”就等价于访问“大儿子”；访问完左子树后去访问“右子树”（其实就是右边的兄弟），因为右指针连着亲兄弟，这就等价于依次去访问“二儿子”、“三儿子”。所以两者的输出顺序**完全一致**。

## 普通树后根遍历=\=二叉树中序遍历

这是这种表示法中最精妙的部分！普通树是没有“中根遍历”的（因为它可能有3个或更多孩子，你不知道把父亲插在哪个孩子中间）。但是，**转换后二叉树的中序遍历，完美等价于普通树的后根遍历。**

- **普通树的后根顺序：** 大儿子 $\rightarrow$ 二儿子 $\rightarrow$ 三儿子... $\rightarrow$ 父亲。
    
- **二叉树的中序顺序：** 左子树 $\rightarrow$ 根 $\rightarrow$ 右子树。
    
- **对应关系剖析：** 1. 先走“左子树”，意味着先去处理**大儿子的所有后代**，最后访问大儿子自己。
    
    2. 大儿子处理完后，本该访问“根（父亲）”了。但等等！二叉树的中序遍历是“左 $\rightarrow$ 根 $\rightarrow$ 右”。在父亲节点去处理它的右子树之前，父亲的访问确实会被触发，**但其实对于一棵普通树的绝对根节点来说，它没有右兄弟（右指针为空），所以根节点永远是最后一个被访问的。**
    
    3. 对于内部节点（比如大儿子），它的“右子树”全都是它的亲兄弟（二儿子、三儿子）。按照二叉树中序遍历的递归法则，它会把所有的兄弟及其子树都处理完。
    
    4. 宏观来看：**先处理左（大儿子家族） $\rightarrow$ 顺着右指针把所有兄弟（其他儿子家族）处理完 $\rightarrow$ 最后才轮到最顶层的父亲。** 这恰恰就是普通树的“后根遍历”逻辑！



这时候，“孩子兄弟表示法”的真正威力就显现出来了：**我们可以用一棵唯一的二叉树，把整个森林完全串起来。**

### 森林转换成二叉树的魔法

回想一下我们上一条探讨的那个“题眼”：对于一棵独立的树，它的绝对根节点是没有兄弟的，所以它的右指针为空。

那如果是一片森林呢？森林里有第一棵树的根、第二棵树的根、第三棵树的根……**这几个根节点，在逻辑上不就是地位完全平等的“亲兄弟”吗？**

所以，森林转二叉树的规则非常简单，只需在单棵树转换的基础上加上一步：

1. **兄弟相连（根的串联）：** 把森林中所有的根节点看作兄弟，用右指针（`next_sibling`）把它们横向串联起来。第一棵树的根指向第二棵树的根，第二棵树的根指向第三棵树的根。
    
2. **各自内部转换：** 对于森林里的每一棵树，在自己内部继续执行标准的“左边连长子，右边连兄弟”转换。
    
3. **整体倾斜：** 最后，以第一棵树的根节点为整棵大二叉树的“绝对根”，所有的右指针斜向右下方。
    

就这么简单，**一片有无数棵树的森林，在物理内存中变成了一棵标标准准的二叉树！**

### 代码层面：为什么说它是完美的？

最令人拍案叫绝的是，表示森林的 C++ 结构体，和表示单棵树的结构体**一模一样，连一个字符都不用改！**

C++

```c
template <typename T>
struct CSNode {
    T data;
    CSNode* first_child;  // 指向自己的第一个孩子
    CSNode* next_sibling; // 指向右边的亲兄弟（或者是森林里下一棵树的根）
};

// 一片森林，只需要保存第一棵树的根节点指针即可！
CSNode<int>* forest_root; 
```

### 森林的遍历等价性

既然森林变成了一棵二叉树，森林的遍历自然也就映射到了这棵二叉树的遍历上：

- **森林的先序遍历**（依次对每棵树进行先根遍历） $\iff$ **二叉树的先序遍历**。
    
- **森林的后序遍历**（依次对每棵树进行后根遍历） $\iff$ **二叉树的中序遍历**。
