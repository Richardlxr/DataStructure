
一个经验公式：**现代 OJ 每秒大约能跑 10⁸ 次简单操作**。

| 数据规模 n | O(n)     | O(n log n) | O(n²)       | O(n³)    |
| ---------- | -------- | ---------- | ----------- | -------- |
| 10⁶        | ~10ms ✅ | ~20ms ✅   | ~10,000s ❌ | —        |
| 10⁵        | ~1ms ✅  | ~2ms ✅    | ~100s ❌    | —        |
| 10⁴        | <1ms ✅  | <1ms ✅    | ~1ms ✅     | ~10s ❌  |
| 10³        | <1ms ✅  | <1ms ✅    | <1ms ✅     | ~10ms ✅ |

估算方法就是把**复杂度代入 n，除以 10⁸**，单位秒：

```/dev/null/estimate.txt#L1-4
O(n²)，n = 10⁵（规模）：
  (10⁵)² / 10⁸ = 10¹⁰ / 10⁸ = 100 秒 → 必然 TLE

O(n)，n = 10⁵：
  10⁵ / 10⁸ = 0.001 秒 → 轻松通过
```

你的题目时限是 1750ms，允许约 **1.75 × 10⁸** 次操作。如果 n 是 10⁵，O(n²) = 10¹⁰ 次，超出约 **57 倍**，所以卡在了极限边缘（1750ms 说明 OJ 给了一点余量但仍然超时）。修复后 O(n) 只用 10⁵ 次，自然飞速通过。
