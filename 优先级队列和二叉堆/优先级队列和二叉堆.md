
    （向下取整） 位置


## 入队

```cpp
    void enQueue(const T & x) {
        // 1. 如果空间满了，先扩容（哨兵占了一个空间）
        if (currentSize == capacity - 1) {
            doubleSpace();
        }

        // 2. 向上过滤 (Percolate up)
        // 首先在堆的末尾创建一个空穴 (hole)
        int hole = ++currentSize;

        // 3. 开始循环：
        // 条件1：hole > 1 (还没到根节点)
        // 条件2：x < array[hole / 2] (新元素比父亲还要小，不合规矩)
        // 步进：hole /= 2 (空穴跳到父亲的位置)
        for (; hole > 1 && x < array[hole / 2]; hole /= 2) {
            // 把父亲拉下来，填到当前的空穴里
            array[hole] = array[hole / 2];
        }

        // 4. 最后把新元素 x 填入最终找到的合适空穴中
        array[hole] = x;
    }
```

## 出队（从上往下过滤）

```cpp
    T dequeue() {
        if (size == 0) {
            throw std::out_of_range("队列空了，没东西可出了！");
        }

        T minItem = data[1]; // 1. 记录那个真正最小的值（堆顶）
        T lastItem = data[size]; // 2. 拿到数组的最后一个元素
        size--; // 3. 堆的大小减 1

        if (size > 0) {
            percolateDown(1); // 4. 把 lastItem 放到坑位 1，并让它向下沉
        }

        return minItem; // 5. 返回最小值
    }

    private:
        // 向下过滤函数（核心！）
        // hole: 当前空穴的位置（一开始是 1）
        void percolateDown(int hole) {
            int child;
            T tmp = data[hole]; // 先把这个“要下沉”的元素存起来

            // 只要有左孩子，就继续尝试下沉
            for (; hole * 2 <= size; hole = child) {
                child = hole * 2;

                // 1. 选出较小的孩子
                if (child != size && data[child + 1] < data[child]) {
                    child++;
                }

                // 2. 如果孩子比 tmp 小，就把孩子提拔上来
                if (data[child] < tmp) {
                    data[hole] = data[child];
                } else {
                    // 3. 否则，tmp 找到了合适的位置
                    break;
                }
            }
            // 最后把 tmp 放入最终落脚的坑位
            data[hole] = tmp;
        }
```



## 建堆（Floyd算法）

### 1. 为什么不用 `enQueue` 连续插入？
最本能的想法是：开一个空的堆，把 $N$ 个数字用一个 `for` 循环，一个个 `enQueue` 塞进去。
*   每次 `enQueue` 最坏需要爬 $\log N$ 层。
*   $N$ 个元素，总时间复杂度就是 $O(N \log N)$。
*   **姜老师说：太慢了！** 我们有更聪明的办法，只需要 **$O(N)$** 的时间！

---

### 2. $O(N)$ 建堆法的神级操作（Floyd 算法）

这个算法的思想极其霸气：**先不讲规矩，全部塞进去，然后再统一“从下往上”整顿。**

**整顿逻辑（核心！请在脑子里想象一棵树）：**
1.  **叶子节点（最底层）不需要整顿**：因为它们没有儿子，天然符合“父小子大”的规矩。
2.  **谁是第一个需要整顿的人？**：是**最后一个非叶子节点**。在数组里，它的下标刚好是 `currentSize / 2`。
3.  **整顿方法**：从 `currentSize / 2` 这个节点开始，**倒着往前遍历**，一直遍历到根节点（下标 1）。对每个节点执行你刚才学过的 `percolateDown`（向下过滤）。

---

### 3. 代码实现

代码短得不可思议，通常我们会把它写成一个以数组为参数的**构造函数**，加上一个私有的 `buildHeap` 函数：

```cpp
// 1. 根据传入的乱序数组建堆的构造函数
priorityQueue(const T * items, int num) {
    capacity = num + 10; // 留点余量
    array = new T[capacity + 1]; // 记得 +1
    currentSize = num;

    // 第一步：不管三七二十一，按顺序直接塞进数组（从下标 1 开始）
    for (int i = 0; i < num; i++) {
        array[i + 1] = items[i];
    }

    // 第二步：执行 O(N) 建堆魔法
    buildHeap();
}

// 2. 核心算法：buildHeap
void buildHeap() {
    // 从最后一个非叶子节点 (currentSize / 2) 开始，倒序遍历到根节点 (1)
    for (int i = currentSize / 2; i > 0; i--) {
        percolateDown(i); // 把当前节点往下沉到合适的位置
    }
}
```

就这么几行代码，时间复杂度直接从 $O(N \log N)$ 降维打击到了 $O(N)$！


### 4. 为什么这是 $O(N)$？（PPT 第 18 页的数学魔法）

想象你在管理一家几千人的公司。
*   如果你用 $O(N \log N)$ 的方法，相当于**每个人进公司时，都要从底层一路往上汇报**直到找到自己的位置，非常繁琐。
*   而 `buildHeap` 相当于：直接把架构定好，然后**基层员工（叶子节点）根本不需要动**。
*   基层主管（倒数第二层，占了一半的人），最多只需要往下看 1 层。
*   中层领导（占了四分之一的人），最多往下看 2 层。
*   只有 CEO（根节点，1 个人），才需要看 $\log N$ 层。

**绝大多数人都只需要动 0 层或 1 层！** 把所有人的移动次数加起来（用错位相减法求和），结果正好约等于 $N$。所以时间复杂度就是 $O(N)$。
