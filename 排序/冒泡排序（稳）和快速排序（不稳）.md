
# 冒泡排序
```c
template < class KEY, class OTHER >
    void bubbleSort(SET < KEY, OTHER > a[], int size) {
        int i, j;
        SET < KEY, OTHER > tmp;
        bool flag = true; // 记录一趟冒泡中有没有发生过交换（剪枝优化）

        for (i = 1; i < size && flag; ++i) { // size-1次冒泡
            flag = false;
            for (j = 0; j < size - i; ++j) // 第i次冒泡
                // 核心比较逻辑
                if (a[j + 1].key < a[j].key) {
                    tmp = a[j];
                    a[j] = a[j + 1];
                    a[j + 1] = tmp;
                    flag = true;
                }
        }
    }
```

### 这个排序稳定吗？

**结论：非常稳定。**

**原因分析：** 看代码中最核心的那行判断：`if (a[j+1].key < a[j].key)`。 冒泡排序只比较相邻的两个元素。只有当右边的元素**严格小于**左边的元素时，才会发生交换。 如果两个相邻元素相等（`a[j+1].key == a[j].key`），这个条件不成立，它们就不会交换位置。因此，相等元素的相对顺序从头到尾都不会改变，这保证了算法的稳定性。

## 第一步：划分

```cpp
// 一趟划分函数（挖坑填数法），返回基准值最终落入的下标
template <class KEY, class OTHER>
int divide(SET<KEY, OTHER> a[], int low, int high) 
{
    SET<KEY, OTHER> k = a[low]; // 挖出基准值，留下第一个坑
    do {
        // 右指针向左找小，填入左坑
        while (low < high && a[high].key >= k.key) --high;
        if (low < high) { a[low] = a[high]; ++low; }
        
        // 左指针向右找大，填入右坑
        while (low < high && a[low].key <= k.key) ++low;
        if (low < high) { a[high] = a[low]; --high; }
    } while (low != high);
    
    a[low] = k;  // 基准值填入最后一个坑
    return low;  // 返回基准值的位置
}
```

时间复杂度$O(n)$
（可以理解为每个元素滚一次）
### 解释
`a[low]`是基准元素
整体就是low右移、high左移的过程，彼此为对方提供坑

## 第二步：主函数（递归分治）

```cpp
// 快速排序的主函数（递归控制）
template < class KEY, class OTHER >
    void quickSort(SET < KEY, OTHER > a[], int low, int high) {
        // 递归终止条件：当区间长度为 1 或 0 时，说明这部分已经排好了，直接返回
        if (low >= high) {
            return;
        }

        // 1. 执行一趟划分，获取基准值的最终归属位置 mid
        int mid = divide(a, low, high);

        // 2. 分治：对基准值左边的子区间进行递归排序
        quickSort(a, low, mid - 1);

        // 3. 分治：对基准值右边的子区间进行递归排序
        quickSort(a, mid + 1, high);
    }
```

### 为什么这样有效？？
#### 划分（Partition）的绝对物理保证

每次调用 `divide` 之后，基准值落在了 `mid` 位置。此时算法提供了一个绝对的物理保证：

- **左半区** `[low, mid-1]` 中的所有元素，**必然都小于或等于** `a[mid]`。
    
- **右半区** `[mid+1, high]` 中的所有元素，**必然都大于或等于** `a[mid]`。
    

这意味着什么？这意味着**基准值 `a[mid]` 已经永远地呆在了它排序后应该在的最终正确位置上**。在后续的所有操作中，这个元素都不会再被移动了。

那么这样递归，最后每个元素都在对应位置
