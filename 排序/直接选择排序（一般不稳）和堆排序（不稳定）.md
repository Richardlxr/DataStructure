它将数组分为两部分：**已排序区**和**未排序区**。初始时，已排序区为空，所有元素都在未排序区。
### 算法全流程

1. **寻找最小（大）值：** 遍历未排序区的所有元素，找到其中的最小（或最大）元素。
    
2. **交换位置：** 将找到的最小元素与未排序区的**第一个元素**进行交换。
    
3. **扩大已排序区：** 交换完成后，该元素就归入了已排序区，未排序区的边界向后移动一位。
    
4. **重复执行：** 对剩下的未排序区重复第 1 到 3 步，直到未排序区只剩下一个元素，排序完成。
    

---

### 稳定性：不稳定 (Unstable)

直接选择排序是一个**不稳定**的排序算法。

**为什么不稳定？**

稳定性的定义是：如果两个元素相等，排序后它们原本的先后顺序保持不变。而在选择排序中，为了把找到的最小元素放到未排序区的头部，我们需要进行**跨越式的交换**，这很容易破坏相等元素的相对顺序。

**举个经典的例子：**

假设我们有一个数组：`[5(A), 8, 5(B), 2, 9]` （我用 A 和 B 标记两个相同的 5 以区分位置）。

- **第一趟排序：**
    
    - 在未排序区 `[5(A), 8, 5(B), 2, 9]` 中找最小值。最小值是 `2`。
        
    - 将 `2` 与未排序区的第一个元素 `5(A)` 交换。
        
    - 数组变成：`[2, 8, 5(B), 5(A), 9]`
        
- **结果分析：**
    
    仅仅经过第一趟排序，`5(A)` 就被扔到了 `5(B)` 的后面。原本在前面的 `5(A)` 现在跑到了后面，相对顺序被破坏了。因此，它是不稳定的。
    

---

### 复杂度总结

- **时间复杂度：** $O(n^2)$。无论数组初始状态如何（即使已经是完全有序的），选择排序都会“傻傻地”遍历未排序区寻找最小值。所以它的最好、最坏、平均时间复杂度全都是 $O(n^2)$，效率较低。
    
- **空间复杂度：** $O(1)$。原地排序，只需要极少的额外空间用于变量交换。
    

为了让你更清晰地看到它是如何“挑挑拣拣”并发生跨越式交换的，我为你准备了直接选择排序的交互式演示：

## 稳定写法？？

### 1. 数组实现：把“跨越交换”改为“平移插入”

回顾一下，标准版之所以不稳定，是因为找到最小值后，直接把它和未排序区的第一个元素互换，这个“互换”动作会把原本在前面的元素扔到后面去。

如果要保持稳定，我们可以不交换，而是**平移**：

- 找到未排序区的最小值。
    
- 将未排序区首位到最小值前一位的所有元素，**整体向后平移一位**。
    
- 将最小值放到未排序区的首位。
    

**举个例子：** `[5(A), 8, 5(B), 2, 9]`

- 找到最小值 `2`。
    
- 不把 `5(A)` 和 `2` 互换，而是把 `5(A), 8, 5(B)` 整体后移一位。
    
- 把 `2` 放到前面。
    
- 结果变成：`[2, 5(A), 8, 5(B), 9]`。
    
- 这样 `5(A)` 依然在 `5(B)` 前面，排序变得**稳定**了。
    

**底层代价：**

这种做法虽然实现了稳定，但在实际的底层实现中是有很大代价的。数组的频繁平移会导致大量的内存写操作（数据移动次数从原本的 $O(n)$ 级别飙升到了 $O(n^2)$ 级别）。选择排序原本最大的物理优势就是“内存写入（交换）次数极少”，改为平移后，它反而变成了一个劣化的插入排序。

### 2. 链表实现：摘取与拼接

如果在**链表**结构上实现选择排序，它天生就可以非常容易地写成稳定的。

- 遍历未排序的链表，找到值最小的节点。
    
- 直接将这个最小节点从原链表中**摘除**（修改前后节点的指针）。
    
- 将它**拼接**到已排序链表的尾部。
    

因为链表的节点移动不需要像数组那样“跨越”其他元素或者大面积平移内存，你只需要保证在遇到相同值的节点时，总是优先摘取最靠前的那个节点，就能完美保持相等元素的初始相对顺序，从而实现稳定排序。

    /**
     * ╔══════════════════════════════════════════════════════╗
     * ║          建堆函数（Floyd 线性建堆法）                  ║
     * ╚══════════════════════════════════════════════════════╝
     *
     * 【功能】
     *   把一个普通的无序数组，一次性调整成一棵合法的最小堆。
     *
     * 【两种建堆方式的对比】
     *   方式一：逐个 enqueue()  → O(n log n)  慢
     *   方式二：Floyd 建堆法    → O(n)        快  ← 本函数采用
     *
     * 【核心思想：数组 = 完全二叉树】
     *   用数组下标来模拟父子关系，下标从 1 开始：
     *
     *              data[1]              ← 根节点（堆顶，最小值）
     *             /        \
     *         data[2]     data[3]
     *         /    \       /    \
     *     data[4] data[5] data[6] data[7]
     *
     *   规律：
     *     节点 i 的左孩子  = 2*i
     *     节点 i 的右孩子  = 2*i + 1
     *     节点 i 的父节点  = i / 2
     *
     * 【为什么从 size/2 开始？】
     *   下标 > size/2 的节点全是叶子节点（没有孩子），
     *   单个叶子天然满足堆性质，不用处理。
     *   只需从最后一个"有孩子的节点"（下标 = size/2）
     *   向左、向上逐个执行"向下过滤"，就能建出整棵堆。
     *
     * 【时间复杂度】O(n)
     * 【空间复杂度】O(1)（不算存储数组本身）
     *
     * @param arr  原始无序数组（下标从 0 开始的普通 C 数组）
     * @param n    数组中元素的个数
     */
    void buildHeap(T * arr, int n) {
        // ── 第一步：按需扩容 ─────────────────────────────────────────
        if (n > capacity) {
            delete[] data;
            capacity = n;
            data = new T[capacity + 1]; // +1：下标 0 闲置
        }

        // ── 第二步：把外部数组的数据拷入堆（堆下标从 1 开始）──────────
        size = n;
        for (int i = 0; i < n; i++) {
            data[i + 1] = arr[i]; // arr[0]→data[1], arr[1]→data[2], …
        }

        // ── 第三步：Floyd 建堆 ────────────────────────────────────────
        //
        // 从最后一个非叶节点（下标 = size/2）开始，一路往根的方向走，
        // 对每个节点调用 percolateDown()，让它"沉"到正确的位置。
        //
        // 以 7 个元素为例（size/2 = 3），处理顺序：
        //   i=3 → i=2 → i=1（根）
        //
        for (int i = size / 2; i >= 1; i--) {
            percolateDown(i);
        }
        // 循环结束：每个父节点都 ≤ 它的两个子节点，堆性质成立！
    }
