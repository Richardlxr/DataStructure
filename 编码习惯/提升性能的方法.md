### 军规 1：极其吝啬地对待 `new` 和 `delete`（避开内核态切换）

**物理真相**：在栈（Stack）上分配内存，只需要移动长尾夹（`sub %rsp`），耗时几乎为 **0 纳秒**。而在堆（Heap）上使用 `new`，会触发操作系统的**系统调用（System Call）**，CPU 必须从用户态切换到内核态，去遍历内存碎片链表寻找合适的空间，甚至可能引发缺页中断（Page Fault）。这动辄需要**几百甚至上千纳秒**。

*   **新手做法**：在 `while` 循环里不断 `push_back` 或者 `new Node`，疯狂触发扩容和系统调用。
*   **硬核做法**：**永远预分配（Pre-allocate）**。
    *   如果你知道最大数量是 `n`，立刻写 `vector<int> res(n)` 或 `ArrayStack s(n)`。
    *   如果数量不确定但有上限，用 `reserve(n)`（只分配物理内存，不构造对象）。

### 军规 2：白嫖 CPU 的 L1/L2 缓存（Cache Line 局部性）

**物理真相**：CPU 永远不会只从内存条里读 1 个字节。当你要读 `arr[0]` 时，内存控制器会把 `arr[0]` 到 `arr[15]`（通常是连续的 64 字节，称为一个 Cache Line）一次性打包全部塞进 CPU 最快的 L1 缓存里。

*   **新手做法**：喜欢用链表（Linked List），或者跳跃着访问数组（比如先读 `arr[0]`，再读 `arr[1000]`）。这会导致 **Cache Miss（缓存未命中）**，CPU 只能被迫停工，去缓慢的内存条里重新拉数据（耗时增加 100 倍）。
*   **硬核做法**：==**数据结构越连续越好，遍历越顺序越好。** 优先用数组代替链表==；如果是二维数组，永远是**按行遍历**，绝对不要按列遍历！

### 军规 3：传参时消灭深拷贝（斩断 8MB 栈溢出的根源）

**物理真相**：当你把一个 `vector` 或 `string` 作为参数传给函数时，如果按值传递，CPU 会在内存里完整地克隆一份一模一样的数据。如果它是 10MB，每次调用函数都要复制 10MB。

*   **新手做法**：`void process(string s, vector<int> nums)`
*   **硬核做法**：**大对象永远传 `const` 引用**。
    *   写成 `void process(const string& s, const vector<int>& nums)`。
    *   物理层面：只传递了一个 8 字节的指针，外加告诉编译器“不准修改它”。时间开销从 $O(n)$ 瞬间降维到 $O(1)$。

### 军规 4：写平滑的指令流（避免 CPU 分支预测失败）==（少用if-else）==

**物理真相**：现代 CPU 内部有一条极长的“流水线”。遇到 `if-else` 时，CPU 不会等条件算完，而是会**“猜”**一条路提前执行（这叫分支预测）。如果猜错了，CPU 必须把流水线里算到一半的废料全部清空，重新走另一条路（大约浪费 15-20 个时钟周期）。

*   **新手做法**：在极高频的 `for` 循环内部，写极其复杂的 `if-else` 嵌套。
*   **硬核做法**：**用数学运算代替分支，或者把分支移到循环外面。**
    *   *举例*：与其写 `if (x < 0) x = 0;`，有时候高级工程师会写 `x = x & ~(x >> 31);`（位运算，强制去负号，0 分支）。
    *   *你的单调栈重构*：我们去掉了 `if (*it < ...)`，直接用 `while` 吞噬所有逻辑，就是为了让 CPU 的指令流更平滑。

### 军规 5：多用前置自增 `++i` 少用后置自增 `i++`

**物理真相**：对于内置类型（如 `int`），两者在现代编译器下没区别。但如果你在迭代器（`iterator`）或者自定义类上使用 `i++`，按照 C++ 标准，它必须在内存里**创建一个临时对象的拷贝**来保存自增前的值，然后再自增主体。

*   **新手做法**：`for (auto it = s.begin(); it != s.end(); it++)`
*   **硬核做法**：==**永远使用 `++i` 或 `++it`**==
### 军规 6：极度厌恶除法（`/`）和取模（`%`）

**物理真相**：在 CPU 的 ALU（算术逻辑单元）中，加减法只需要 1 个时钟周期，乘法需要 3-5 个周期，而**整数除法和取模需要 20 到 40 个时钟周期！** 它是基本运算里最慢的硬件指令。

*   **新手做法**：经常用 `/ 2` 或 `% 2` 来判断奇偶。
*   **硬核做法**：
    *   算 `x / 2`，写成 `x >> 1`（右移 1 位，仅需 1 周期）。
    *   算 `x * 2`，写成 `x << 1`。
    *   判断奇偶 `x % 2 == 1`，写成 `x & 1`（按位与，极速获取最后一位的电平信号）。
