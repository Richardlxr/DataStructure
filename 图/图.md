#### 1. 图的分类与基础定义

- **结点/顶点 (Vertex)**：图的基本元素。在有向图中，边由**弧尾（初始结点）**指向**弧头（终止结点）** 。
    
- **无向图 (Undirected Graph)**：边没有方向，通常用小括号表示边，如 $(V_i, V_j)$。常用于表示合作网络等双向关系 。
    
- **有向图 (Directed Graph)**：边有方向（也叫弧），通常用尖括号表示弧，如 $<V_i, V_j>$。常用于表示文献引用、网页链接等单向关系 。
    
- **加权图 / 网络 (Weighted Graph / Network)**：图的边附带有“权值”（如距离、成本、时间等） 。
    

#### 2. 顶点的度 (Degree)

衡量一个顶点的“连接程度”。

- **无向图**：直接与该顶点相连的边的总数 。
    
- **有向图**：分为**出度 (Out-degree)**（从该顶点发出的弧的数量）和**入度 (In-degree)**（指向该顶点的弧的数量） 。
    

#### 3. 连通性 (Connectivity)

**对于无向图：**

- **路径 (Path)**：由顶点 $v_i$ 到 $v_j$ 之间的顶点序列 。
    
- **简单回路 / 简单环**：除第一个和最后一个顶点相同外，其余顶点**不重复出现**的路径 。
    
- **连通图**：任意两点之间都有路径相连 。
    
- **连通分量 (Connected Component)**：无向图的**极大连通子图**（不能再扩充的连通块） 。
    

**对于有向图：**

- **强连通图**：任意两点之间都存在**双向路径**（即 $v_i$ 能到 $v_j$，$v_j$ 也能到 $v_i$） 。
    
- **弱连通图**：把有向边当成无向边看，如果它是连通的，就叫弱连通图 。
    
- **强连通分量**：有向图的**极大强连通子图** 。
    

#### 4. 树与完全图 (特殊形态的图)

- **生成树 (Spanning Tree)**：极小连通子图。包含全部 $n$ 个结点，但只有恰好 $n-1$ 条边。如果加上任何一条新边，必定会形成回路 。
    
- **无向完全图**：任意两个顶点间都有一条边，总边数为 $n(n-1)/2$ 。
    
- **有向完全图**：任意两个顶点间都有方向相反的两条边，总边数为 $n(n-1)$ 。
    

### 图的存储结构 (Graph Storage)

#### 方案一：邻接矩阵 (Adjacency Matrix)

**核心思想**：用一个二维数组（矩阵）来表示所有的边。

- **机制**：设图有 $n$ 个顶点，建立一个 $n \times n$ 的布尔矩阵 `A` 。
    
    - 如果有向图从顶点 $i$ 到 $j$ 有一条边，则 `A[i][j] = 1`（无边则为 `0`） 。
        
    - 如果是加权图，有边则存权值 `A[i][j] = weight`，无边则存一个特殊标记（如 `∞` 或 `-1`） 。
        
- **无向图特权**：无向图的邻接矩阵一定是对称的（因为 $i$ 到 $j$ 有边，$j$ 到 $i$ 必定有边）。顶点的度就是第 $i$ 行（或列）的元素之和 。
    
- **优缺点**：
    
    - ✅ **优点**：查找任意两点间是否有边极其快速（时间复杂度 $O(1)$） 。
        
    - ❌ **缺点**：极其浪费空间。即使图里只有几条边，也要强行开辟 $n^2$ 的内存空间（空间复杂度 $O(|V|^2)$） 。适合稠密图。
        

#### 方案二：邻接表 (Adjacency List)

**核心思想**：数组 + 单链表的组合拳。只存实际存在的边，绝不浪费。

- **机制**：
    
    - 用一个一维数组（或顺序表）保存所有的顶点 。
        
    - 每个顶点都拖着一条单链表，链表里装的都是它的“邻接点”（无向图）或“出度目标点”（有向图） 。
        
- **空间消耗**：只需要 `结点数 + 边数` 的空间（空间复杂度 $O(|V| + |E|)$），对内存极其友好 。
    
- **优缺点**：
    
    - ✅ **优点**：极度省空间，适合边较少的稀疏图 。找一个顶点的所有邻居非常快。
        
    - ❌ **缺点**：想判断顶点 A 和顶点 B 是否直接相连，只能老老实实去遍历 A 的那条单链表，速度不如矩阵快。

## 深度优先搜索（dfs）


### 标准图论dfs
- **helper（雷达/大管家）：** 负责在天上飞，寻找那些还没被发现的“孤岛”（孤立的连通块）。
    
- **dfs（病毒/打工人）：** 一旦被 helper 空投到某个孤岛上，就立刻疯狂蔓延，顺着错综复杂的道路，**一次性**把这座岛上所有能连通的城市**全部染红**。
    

染红完这座岛后，dfs 任务结束。helper 继续转动雷达，去寻找下一个还没被染红的孤岛，重复这个过程，直到全世界全红。

```c
    void dfs(int index, bool visited[]) {
        visited[index] = true;
        std::cout << verList[index].ver << '\t';
        edgeNode * p = verList[index].head;
        while (p != nullptr) {
            if (!visited[p - > end]) { // 只有没去过，才进去DFS
                dfs(p - > end, visited);
            }
            p = p - > next; // 无论去没去过，看完这扇门，都要看下一扇门
        }
    }


    void dfs_helper() const {
        bool * visited = new bool[this - > Vers];
        for (int i = 0; i < this - > Vers; i++) {
            visited[i] = false;
        }

        std::cout << "Depth-First Search" << '\n';

        for (int i = 0; i < this - > Vers; i++) {
            if (visited[i] == true)
                continue;
            dfs(i, visited);
            std::cout << '\n';
        }
    }
```


## 回溯DFS

```c
// 全局状态变量
int path[MAXN];
bool used[MAXN];

void dfs(int step) {
    // 1. 终点判断（有没有填满坑）
    if (step == 终点) {
        记录答案 / 打印 path;
        return;
    }

    // 2. 枚举当前步骤所有可能的选择
    for (int i = 1; i <= 可选数量; i++) {

        // 3. 检查这个选择合不合法 (剪枝)
        if (没被用过 && 满足题目特定条件) {

            // 4. 做选择
            path[step] = i;
            used[i] = true;

            // 5. 递归进入下一步
            dfs(step + 1);

            // 6. 撤销选择（恢复现场，尝试下一种可能）
            used[i] = false;
        }
    }
}
```

### 主要区别：“回溯”为什么一定要 `used[i] = false`（恢复现场）？

这是这个模板和之前“图论 DFS”**最大的区别**：
* 在图论里走迷宫，走过的房间就画个叉，**不用擦掉**，因为我们的目的是把所有房间逛一遍，不想走回头路。
* 在回溯法里，你在做==**组合/排列**。==
  * 假设你想排 `1, 2, 3`。
  * 第一条路你排了 `[1, 2, 3]`，这时候 `used[1]、used[2]、used[3]` 都是 `true`。
  * 当你要尝试第二条路 `[1, 3, 2]` 的时候，如果你不把 `used[2]` 和 `used[3]` 变回 `false`（不把卡片退还给牌堆），你就没有卡片可用了！
  * **所以，`dfs(step+1)` 跑完退回来的时候，必须把拿走的数字还回去（`used[i] = false`），这就是“回溯”二字的真正含义。**

# 欧拉回路
### 一、 故事起源：七桥问题（哥尼斯堡七桥）
**欧拉的神级抽象：**
他根本不关心岛有多大、桥有多长。他把 **4 块陆地画成 4 个【节点】**，把 **7 座桥画成 7 条【边】**。
于是，真实世界的散步游戏，变成了纸上的“一笔画”**问题。
![[Königsberg_graph.svg.png|637]]
### 二、 核心概念辨析：通路 vs 回路

在纸上玩“一笔画”，有两种通关方式：

1. **欧拉通路（Euler Path）：** 一笔画完所有的边，但不要求回到起点。（从 A 点进，最后停在 B 点）。
2. **欧拉回路（Euler Circuit）：** 一笔画完所有的边，而且**必须回到起点**！（从 A 点进，画完一圈，最后笔尖停回 A 点）。

> **总结：** 包含欧拉回路的图叫“欧拉图”，包含欧拉通路的图叫“半欧拉图”。

---

### 三、 欧拉的神级推导：“度数”的魔法

为什么欧拉能一眼看出七桥问题无解？因为他发现了一个极其直观的数学规律，这就是欧拉回路的**判定定理**。

我们需要先认识一个词：**度（Degree）**。
* **度数** = 连着这个节点的边的数量。也就是这个城市的“出入口总数”。

#### 💡 欧拉回路的必杀判定（针对无向图）：
**“如果一个图有欧拉回路，那么所有节点的度数，必须全部是【偶数】！”**

**为什么？（大白话解释）**
你想啊，你要把所有的路都走一遍，这意味着：
对于任何一个普通的中间城市，你只要“进”**去一次，就必须从另一条路**“出”**去一次。
“一进一出”，必定成双成对！**
所以，只要你路过这个城市，就消耗掉它 2 条路。哪怕你路过它 100 次，也会消耗掉它 200 条路。
就连你的**起点/终点**，你一开始“出”去，最后一步“进”来，也是成对消耗的！
**结论：任何存在“奇数度数”节点的图，绝对不可能一笔画完并回到原点！**

#### 💡 欧拉通路的判定：
如果你不要求回到起点，可以停在别的地方呢？
* **起点：** 第一步只“出”不“进”，所以起点消耗了 1 条路（它是奇数）。
* **终点：** 最后一步只“进”不“出”，所以终点也消耗了 1 条路（它是奇数）。
* **中间点：** 依然是一进一出，全是偶数。
**结论：“一笔画但回不到原点”的图，【必定且只能有 2 个】奇数度数的节点！**

---

### 四、 审判七桥问题

现在，我们用欧拉的魔法来审判哥尼斯堡的市民。
画出哥尼斯堡的图后，欧拉数了一下 4 块陆地的桥的数量（度数）：
* 陆地 A：连着 3 座桥（奇数）
* 陆地 B：连着 3 座桥（奇数）
* 陆地 C：连着 3 座桥（奇数）
* 陆地 D：连着 5 座桥（奇数）

**全特么是奇数！**
别说“所有度数全是偶数（欧拉回路）”了，它连“只有 2 个奇数（欧拉通路）”的要求都达不到！
所以欧拉直接断言：不管你们从哪里出发，这 7 座桥绝对不可能不重不漏地走完。

---

### 五、 我们怎么用代码找欧拉回路？
![[截屏2026-06-09 20.57.29.png|637]]

* **之前的 DFS：** 给**节点**打 `visited` 标记。（节点黑名单）
* **欧拉的 DFS：** 给**边**打 `visited` 标记。（道路黑名单）
### 第一步：

我们要从节点 `5` 开始做 DFS。记住，我们现在的规则是：**只要这条路没走过，就可以走；去过的节点还能再去。**

1. 站在 **5**。5 连着两扇门：去 4，去 3。
   * 假设程序挑了去 **4** 的门（把边 5-4 标记为“已走”）。
2. 来到 **4**。4 连着四扇门，但 4-5 刚走过，还剩：去 3、去 2、去 1。
   * 假设程序挑了去 **3** 的门（把边 4-3 标记为“已走”）。
3. 来到 **3**。3 也连着四扇门，3-4 刚走过，还剩：去 5、去 2、去 1。
   * 假设程序挑了去 **5** 的门（把边 3-5 标记为“已走”）。
4. 再次回到 **5**。此时看看 5 剩下的门：没有了！5-4 和 5-3 都走过了。
   * **此时无路可走，DFS 结束！**
   * 我们得到了第一条路径：`5 -> 4 -> 3 -> 5`。

**💡 欧拉神级定律在这里起作用了：**
还记得上一条说的“所有节点的度数都是偶数（一进一出）”吗？
因为所有的点都是偶数度，所以只要你随便走，**你绝对不可能在中间节点卡死**（因为进得去就一定出得来）。**你唯一无路可走的地方，必然是你一开始出发的起点！**
所以，这第一次盲目的 DFS，一定会自动形成一个**环（圈）**！

---

### 第二步：核心科技“圈套圈”（路径拼接）

第一步我们画出了一个小圈 `5->4->3->5`。但是图上还有很多路没走啊！怎么办？

老师的第二张幻灯片给出了绝妙的解法：**“在刚才的路径上，找一个还有剩余道路没走的节点，把它作为新起点，再画一个圈！”**

1. 我们检查路径 `5 -> 4 -> 3 -> 5` 上的节点。
   * 检查 5：没路了。
   * 检查 **4**：哎！节点 4 还有两条路（4-1，4-2）没走过！
2. 好，我们**把 4 当作新的起点**，继续用刚才的 DFS 瞎走：
   * 从 4 出发 -> 走 2 -> 走 1 -> 又没路了，必定回到 4！
   * 我们得到了第二个圈：`4 -> 2 -> 1 -> 4`。
3. **“偷梁换柱”（拼接）：**
   * 原来的路径是：`5 -> [4] -> 3 -> 5`。
   * 我们在原来走到 `4` 的时候，先不去 `3`，而是去逛一圈新发现的环，逛完回到 `4` 之后，再继续往 `3` 走。
   * 把新圈塞进原来的 `[4]` 的位置，就变成了：
   * `5 -> [4 -> 2 -> 1 -> 4] -> 3 -> 5`。

---

### 第三步：继续套圈，直到全图走完

现在的总路线是：`5->4->2->1->4->3->5`。
我们继续检查这条路上的节点，看谁还有路没走：
* 5没路了，4没路了，2还有路（2-0, 2-3），1还有路（1-0, 1-3），**3**还有路（3-1, 3-2, 3-0，等等）。
* 老师 PPT 里挑了节点 **3** 作为新起点。
* 从 3 开始新的 DFS：`3 -> 1 -> 0 -> 2 -> 3`。（必定又是一个圈）

**最后一次拼接：**
* 我们把这个新圈，塞进总路线中 `[3]` 的位置。
* 原路线：`5->4->2->1->4-> [3] ->5`
* 拼接后：`5->4->2->1->4-> [3 -> 1 -> 0 -> 2 -> 3] -> 5`

**完美！所有的边都恰好走了一次，一笔画完成！**

# 拓扑排序
### 一、 现实场景：你要怎么选课？

理解拓扑排序，最好的例子就是**大学选课**或者**打游戏的技能树**。

假设计算机专业有 5 门课，它们之间有严格的**“前置要求”**：
1. 《C语言》（无前置要求，大一新生直接上）
2. 《离散数学》（无前置要求）
3. 《数据结构》（**必须先学**《C语言》）
4. 《算法分析》（**必须先学**《数据结构》和《离散数学》）
5. 《高级图论》（**必须先学**《算法分析》）

**问题来了：** 作为辅导员，你需要给学生排一个课表（学习顺序），保证学生在学任何一门课之前，都已经把它的前置课程学完了。

**这个排课表的动作，就叫做“拓扑排序”！**
**排出来的一份合法的课表顺序，就叫“拓扑序列”。**

（比如：`C语言 -> 离散数学 -> 数据结构 -> 算法分析 -> 高级图论` 就是一个合法的拓扑序列）。

---

### 二、 图论视角的抽象（AOV网）

我们把上面的选课关系画成图：
* **节点（Vertex）：** 代表课程（任务）。
* **有向边（Directed Edge）：** $A \to B$ 代表“A 是 B 的前置条件”（必须先完成 A，才能做 B）。

这里引出拓扑排序的两个**生死前提**：
1. **必须是有向图：** 依赖关系必须有明确的先后方向。
2. **绝对不能有环（DAG，有向无环图）：** 
   * 想象一下如果图里有个环：学《数据结构》必须先学《C语言》，学《C语言》必须先学《离散数学》，学《离散数学》必须先学《数据结构》。
   * 完蛋了！这成了“先有鸡还是先有蛋”的**死锁（Deadlock）**！学生这辈子都毕不了业。
   * 所以，**只要图里有环，就绝对做不出拓扑排序！**

---

### 三、 怎么排？（核心概念：入度）

我们不看代码，就用人类的直觉来排这 5 门课。这里要引入一个极其核心的词：**入度（In-degree）**。

* **入度的大白话解释：** 还有几门前置课没学？（或者说，这扇门上还挂着几把锁？）

**手工推导流程：**

**第一步：找“软柿子”捏（找入度为 0 的节点）**
* 扫一眼所有课程，谁的入度是 0（没有任何前置要求）？
* 找到了：《C语言》（入度0）和《离散数学》（入度0）。
* 我们随便挑一个，比如先把 **《C语言》** 学了！把它写进课表第一位。

**第二步：过河拆桥（消除影响）**
* 既然《C语言》已经学完了，那它作为别人前置条件的限制就解除了！
* 我们在图上**把《C语言》这个节点，以及从它发出的所有箭头，全部擦掉！**
* 此时，《数据结构》原本有一个前置（C语言），现在限制解除了，它的**入度从 1 变成了 0**。

**第三步：循环往复，直到所有课学完**
* 现在图上剩下的课里，谁的入度是 0？
* 发现：《离散数学》（入度0）和《数据结构》（入度0）。
* 我们挑 **《数据结构》** 学了，写进课表第二位。然后把《数据结构》和它的箭头擦掉。
* 接着擦掉箭头后，《算法分析》的入度变少了……

就这样，**每次找一个没有前置要求（入度为0）的事情做，做完就把它从图里划掉，直到把整个图划空。** 这就是拓扑排序的全部运作原理！

---

### 四、 拓扑排序的几个重要特征

1. **答案不唯一：** 
   就像刚才第一步，大一新生既可以先学《C语言》，也可以先学《离散数学》。所以同一个图，可能排出来好几种合法的拓扑序列，它们都是正确的。
2. **可以用来“测谎”（检测环）：**
   假设你在“找入度为0的节点”时，图里的节点还没划完，你却发现**全场竟然没有一个入度为 0 的节点了**！大家互相指着对方说“你先上”。
   这就说明：**图里一定藏着一个环！** 这个项目死锁了，永远无法完工。这也是拓扑排序在工程中最常用的功能之一（比如检查软件包的循环依赖）。

# 关键路径
### 一、 视角切换：从 AOV网 到 AOE网

在刚才的拓扑排序里，图的**节点（顶点）代表事情（比如《C语言》），这叫 AOV网**（顶点表示活动）。
但是在关键路径里，图的**边（箭头）代表事情，而节点只代表**“里程碑（状态）”**！这叫 AOE网**（边表示活动）。

**举个极其生动的例子：造房子**
* **节点（圆圈）：** 代表项目进度里程碑。比如节点 1 是“开工”，节点 2 是“地基打完”，节点 3 是“墙砌完”。**（里程碑本身不耗费时间，只是个打卡点）**。
* **边（箭头）：** 代表具体的施工任务，**边上带有时间（权重）**！比如 `1 -> 2` 代表“打地基”，耗时 5 天。

---

### 二、 核心问题：老板的两个灵魂拷问

假设你是一个工程总监，手下有水电工、泥瓦工可以**同时（并行）干活**。老板把你叫到办公室，问了你两个致命问题：

1. **“这个工程最快到底需要几天才能全干完？”**
2. **“我要去现场监工，盯紧哪些工序绝对不能出岔子（拖延）？”**

为了回答这两个问题，前人发明了“关键路径算法”。它的核心思路就是计算**时间的“极限”**。

---

### 三、 两个方向的时间推演（正推与逆推）

要找出关键路径，我们要算四个时间（但别怕，逻辑极其简单）：

#### 1. 正向推导：里程碑的“最早达成时间”（木桶原理：取最大值！）
假设有一个里程碑叫“准备装修”。
* 泥瓦工说：“我把墙砌好需要 5 天。”
* 水电工说：“我把管子铺好需要 10 天。”
* **请问：“准备装修”这个里程碑，最早能在第几天达成？**
* **答案是：第 10 天！** 因为必须等**最慢**的那个干完，下一个阶段才能开始。
> **总结：正向推导（从起点到终点），遇到汇合点，总是取时间【最长/最大】的那个。最终终点的时间，就是整个项目完工的【最短总工期】！**（回答了老板的第一个问题）

#### 2. 逆向推导：里程碑的“最迟必须开工时间”（赶班车原理：取最小值！）
好，现在整个项目敲定最快 30 天干完。老板下死命令：**第 30 天必须交房，一天都不能晚！**
我们从第 30 天开始**往回倒推**。
假设“刷漆”任务需要 5 天，那么“开始刷漆”这个里程碑，**最迟最迟**必须在第 25 天（30 - 5）开始。
如果一个节点后面跟着两个任务：
* 任务 A 需要 5 天，要在 30 天交工，最迟 25 天必须开始。
* 任务 B 需要 10 天，要在 30 天交工，最迟 20 天必须开始。
* **请问：这个里程碑最迟必须在第几天达成？**
* **答案是：第 20 天！** 因为如果你拖到 25 天，任务 A 能按时完成，但任务 B 绝对完不成了！
> **总结：逆向推导（从终点回起点），遇到分叉点，总是取时间【最早/最小】的那个。**

---

### 四、 见证奇迹的时刻：寻找“机动时间”（Slack）与“关键路径”

现在，我们对图里的每一个具体的**施工任务（边）**，都拥有了两个时间：
1. **最早能开始的时间**（取决于前置任务最快啥时候干完）
2. **最晚必须开始的时间**（取决于不能耽误最终交房日期）

**【机动时间】 = 最晚必须开始时间 - 最早能开始时间**

* **场景 A：** 铺地砖最早第 10 天就能开始，最晚第 15 天必须开始。
  * 机动时间 = 5 天。
  * 意味着铺地砖的工人可以**摸鱼（拖延）5 天**，老板根本不急，因为不会影响最后交房。
* **场景 B：** 打地基最早第 0 天开工，最晚第 0 天必须开工。
  * 机动时间 = 0 天！
  * 意味着打地基的工人**一秒钟都不能摸鱼！** 只要他慢一天，整个项目最终交房就会晚一天！

#### 🎯 终极结论：
**那些【机动时间为 0】的任务（边），就是“关键活动”！**
**把所有“关键活动”连在一起，从起点通向终点的那条（或多条）线，就叫【关键路径（Critical Path）】！**

老板的第二个问题也解答了：去现场监工，不用看铺地砖的工人，死死盯着“打地基”、“砌主墙”这些在关键路径上的工人就行了！

### 五、 它和“拓扑排序”有什么联系？

你可能会问，怎么算“正向推导”呢？
这就是拓扑排序的用武之地了！

因为你必须**先把前面的里程碑时间算出来，才能算后面的里程碑**。所以，计算所有里程碑的最早时间时，我们正是**严格按照【拓扑排序的顺序】**去遍历图的！没有拓扑排序，关键路径连第一步的正向推导都做不了。

**小结一下关键路径的核心动作：**
1. 拓扑排序正着走一遍 $\rightarrow$ 算出每一个打卡点的最早时间（取MAX）。
2. 逆着拓扑排序退回来一遍 $\rightarrow$ 算出每一个打卡点的最晚时间（取MIN）。
3. 两者一减，得数为 0 的路 $\rightarrow$ **关键路径！**
