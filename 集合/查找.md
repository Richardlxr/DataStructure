## 第一部分：集合与静态查找表 (Static Search)

静态查找表适用于集合结点总数固定或极少变化的场景，重点在于减少比较次数 。

### 1. 顺序查找 (Sequential Search)

适用于无序的顺序表或链表 。

- **哨兵机制**：在顺序存储中，0 号单元用作“哨兵”存放待查关键字，1 到 n 号单元保存实际结点 。
    
- **哨兵的优势**：避免了在循环中每次都检查数组越界（即省去 `i >= 0` 的判断），提高了基础操作的效率 。
    
- **性能分析 (ASL - 平均查找长度)**：
    
    - 成功查找（等概率）：$ASL = \sum_{i=1}^{n} \frac{n-i+1}{n} = \frac{n+1}{2}$ 。
        
    - 一般情况（成功与失败概率各半）：$ASL = \frac{3(n+1)}{4}$ 。
        

### 2. 折半查找 (Binary Search)

仅适用于**元素有序**的**顺序表**，不可直接用于线性链表 。

- **最坏情况**：最大比较次数为 $1 + \lfloor \log_2 n \rfloor$，可由判定树推导得出 。
    
- **平均情况（成功查找）**：假设树为完全二叉树，平均查找代价约为 $ASL = \log_2(n+1) - 1$ 。
    

### 3. 其他静态查找方法

- **插值查找 (Interpolation Search)**：适用于数据分布比较均匀的情况，通过比例公式 $next = low + \frac{x-a[low]}{a[high]-a[low]} \times (high-low+1)$ 快速定位，但计算复杂 。
    
- **分块查找 (Block Search)**：采用索引顺序块，块之间必须有序，但块内数据可以无序 。

## 第二部分：动态查找表 (Dynamic Search)

动态查找表需要在支持快速查找的同时，高效地处理元素的插入和删除操作 。

### 1. 二叉查找树 (Binary Search Tree, BST)

对于任意非空结点 p，其左子树所有结点的关键字均小于 p，右子树所有结点的关键字均大于 p 。

- **查找 (Find)**：非递归实现效率更高，通过不断比较向左或向右子树迭代即可 。
    
- **插入 (Insert)**：若树空则直接作为根，否则沿着查找路径下降直到遇到 `NULL` 进行插入 。
    
- **删除 (Remove)**：分为三种情况处理 ：
    
    1. **叶结点**：直接删除，父结点指针置空 。
        
    2. **只有一个孩子**：将其唯一子树挂接到父结点上，然后删除该结点 。
        
    3. **有两个孩子**：寻找“替身”结点（左子树最大值或**右子树最小值**）。将替身的数据复制到被删结点，然后在对应子树中递归删除该替身 。
        

- **平均性能**：查找成功时的 $ASL$ 与 $\log_2 n$ 成正比（$\approx 1.38 \log n$），最坏退化为链表结构 。
    

### 2. 平衡二叉树 (AVL Tree)

为了防止 BST 退化，AVL 树强制每个结点的平衡因子（左子树高度减去右子树高度）只能是 +1、-1 或 0 。

- **高度定理**：具有 N 个结点的 AVL 树，高度 h 严格满足 $S(H) = S(H-1) + S(H-2) + 1$，推导出 $\log_2(N+1) \le h \le 1.44\log_2(N+1) - 0.328$，保证了操作的 $O(\log N)$ 复杂度 。
    
- **失衡调整 (Rotations)**：
    
    - **LL 型**：在左孩子的左子树插入导致失衡。做一次单右旋 。
        
    - **RR 型**：在右孩子的右子树插入导致失衡。做一次单左旋 。
        
    - **LR 型**：在左孩子的右子树插入导致失衡。先对左孩子做 RR 旋转，再对根做 LL 旋转 。
        
    - **RL 型**：在右孩子的左子树插入导致失衡。先对右孩子做 LL 旋转，再对根做 RR 旋转 。
        

- **AVL 的删除**：删除可能导致某棵子树变矮，需沿路径向上回溯，通过 `adjust(t, subTree)` 函数检查并修复失衡（处理包含 5 种不同的高度变化情况） 。

## 第三部分：哈希表 (Hash Tables)

哈希表不基于比较，通过哈希函数将关键字直接映射到存储位置，理想时间复杂度为 $O(1)$ 。

### 1. 哈希函数与特性

- **四大特点**：确定性（输入相同输出必相同）、碰撞抵抗性、算法不可逆性、输入敏感性（雪崩效应） 。
    
- **构造方法**：
    
    - **直接地址法**：$H(key) = a \times key + b$ 。
        
    - **除留余数法（最常用）**：$H(key) = key \bmod p$（p 一般为小于等于表长 m 的最大素数） 。
        
    - **数字分析法**、**平方取中法**、**折叠法**：用于长数字特征处理 。
        
    - **MurmurHash**：非加密型高性能哈希算法，如 Redis 中使用 。
        

### 2. 冲突解决策略 (Collision Resolution)

#### 闭散列表 (Closed Hashing / Open Addressing)

冲突发生时，在原表中寻找下一个空单元。结点的状态维护十分关键：`0` 代表空，`1` 代表存在，`2` 代表已删除（Lazy Deletion，保证探测链不断裂） 。

- **线性探测再散列**：$pos = (pos + 1) \bmod size$。缺点是容易产生二次聚集（Secondary Clustering） 。
    
- **二次探测 / 随机探测**：$H(key) = (key + d_i) \bmod p$，其中 $d_i$ 为 $1^2, 2^2 \dots$ 或随机数 。
    

#### 开散列表 (Open Hashing / Chaining)

即拉链法，将哈希到同一地址（同义词）的所有结点，挂载到同一个单链表中。主数组存放的是链表头指针（`node **array`） 。插入通常发生在链表头 ，删除则需执行标准的链表结点移除操作 。
