### 1. 理论精讲
集合（Set）是最基础的逻辑结构之一。
*   **核心特征**：集合中的数据元素除了“属于同一个集合（同类型）”之外，**没有任何其他的逻辑关系**。它们就像散落在同一个口袋里的玻璃球。
*   **唯一标识**：为了区分集合中的元素，我们需要包含唯一标识，称为**键值（Key）或关键字值**。
*   **主要运算**：
    1.  查找某一元素是否存在。
    2.  将集合中的元素按照唯一标识排序。
*   **物理实现（怎么在电脑里存它？）**：
    *   任何容器（数组、链表等）都能存。常用的是借助**线性表**或**树**。
    *   💡 *划重点*：唯一一个**仅适合于**存储和处理集合的数据结构是**散列表（Hash Table）**。

## 二、 静态查找技术与哨兵机制

### 1. 理论精讲
*   **静态 vs 动态**：
    *   **静态搜索表**：集合中的结点总数固定，或很少发生变化。（比如历史成绩单）。
    *   **动态搜索表**：结点总数经常发生变化，频繁插入删除。（比如在线游戏当前存活玩家）。
*   **评价标准（极其重要）**：
    *   **在内存中进行的搜索**：重点是减少比较次数。评价标准是 **平均搜索长度（ASL, Average Search Length）**。
    *   **在外存（硬盘）中进行的搜索**：重点是减少访问外存的次数。评价标准是 **读盘次数**。
*   **顺序存储与“哨兵（Sentinel）”**：
    *   我们开辟数组时，0号单元留空不用作存数据，而是当作“哨兵”。真正的数据保存在1号到n号单元。

> [!important] 核心重点
> **知识点**：==为什么要哨兵？==
> **理解关键**：
> - 如果没有哨兵：for循环每次都要判断：是不是>=0?是不是我要的元素？==两次if==
> - 如果有哨兵：==在0这个位置放我需要的元素==，我只需要一次判断（是不是我要的元素）
>

## 三、 无序表的顺序查找

### 1. 理论精讲
我们要在刚才建立的数组中找一个特定的值 `x`。从后往前扫描。
*   **巧妙的哨兵设计**：令 `data[0].key = x;`。
*   **好处**：我们从位置 `n` 开始倒序循环 `for (int i = size; x != data[i].key; --i);`。因为0号位置就是你要找的 `x`，所以这个循环**永远不会越界**！不需要额外写 `i >= 0` 的判断条件，大大加快了底层汇编的执行速度。

*   **性能分析（ASL推导，必须掌握）**：
    *   **仅考虑查找成功**：设 $n$ 为结点总数，每个结点被查找的概率相等（$1/n$）。查找第 $i$ 个结点需要比较 $n-i+1$ 次。
        $$ASL = \sum_{i=1}^{n} \frac{n-i+1}{n} = \frac{n+1}{2}$$
    *   **一般情况（包含成功与不成功）**：假设查找成功和不成功的概率各一半，每个元素被找到的概率也相等。不成功的时候一定会比较到哨兵（共进行 $n+1$ 次比较）。
        $$ASL = \sum \frac{n-i+1}{2n} + \frac{n+1}{2} = \frac{3(n+1)}{4}$$

## 四、 有序表的顺序查找

### 1. 理论精讲
如果这个数组已经提前排好序了（假设是升序），我们还需要傻傻地走到哨兵才发现没找到吗？
*   **优化逻辑**：从后往前找时，因为前面的数越来越小，如果当前遍历到的数字 `data[i].key` 已经比你要找的 `x` 还要小了，说明前面不可能有 `x` 了，直接可以停止！
*   **代码差异**：`for (int i = size ; x < data[i].key; --i);` 停止后，再判断一下 `if (x == data[i].key)` 即可。

### 2. 👨‍💻 上机训练（Exercise 4）
**任务**：实现有序表顺序查找。
定义有序数组：`[哨兵, 1, 3, 8, 10, 100]`。从后往前查找 `x=5`。当遍历到 `8` 时继续，遍历到 `3` 时发现 `5 < 3` 不成立，退出循环，判断 `5 != 3`，立刻返回查找失败。请写代码验证这个提速过程。

==注意怎么用一次比较，不要违背了哨兵的初衷！！==

```c
int seqSearch(int target) {
    // 1. 设置哨兵：将 target 放在 0 号位置（假设 0 号是哨兵位）
    data[0] = target;

    int i = n;

    // 2. 核心循环：每次只有 1 次比较！
    // 只要当前元素还比 target 大，就安心往前找
    while (data[i] > target) {
        i--;
    }

    // 3. 循环结束，进行“收尾判断”
    // 退出的情况有两种：
    // a. 遇到了比 target 小的数（说明数组前面不可能有 target 了，提前下班）
    // b. 遇到了等于 target 的数（可能是真正找到了，也可能是撞到了 0 号位的哨兵）

    if (i > 0 && data[i] == target) {
        return i; // 找到了，并且不是哨兵位
    } else {
        return -1; // 没找到（或者是碰到了更小的值提前退出，或者是撞到了哨兵）
    }
}
```

## 五、 折半查找（二分查找）核心重难点！

### 1. 理论精讲
这部分是重中之重，请务必打起精神！
*   **适用范围**：**必须是有序的顺序表**（数组）。绝对不可直接用于线性链表（因为链表无法通过下标做 $O(1)$ 时间的中间位置访问）。
*   **核心逻辑**：
    *   定义上下界：`low = 1`, `high = size`。
    *   计算中间位置：`mid = (low + high) / 2`。
    *   如果 `x == data[mid].key`，找到了，返回 `mid`。
    *   如果 `x < data[mid].key`，说明 `x` 在左半边，更新 `high = mid - 1`。
    *   如果 `x > data[mid].key`，说明 `x` 在右半边，更新 `low = mid + 1`。
*   **失败条件**：当 `low > high` 时，循环结束，查找失败。

### 2. 性能分析与“判定树” (Decision Tree)
*   **最坏情况分析**：
    每次折半相当于剥洋葱，最多剥 $k$ 次。设元素个数 $n = 2^k - 1$，比较的最大次数恰好是树的深度 $k$。
    递归方程推导得出结论：最坏比较次数为 $1 + \lfloor \log_2 n \rfloor$。
*   **平均情况分析 (ASL)**：
    *   **完全二叉树视角**：把中间值当根节点，左半边当左子树，右半边当右子树，这就构成了一棵二叉判定树。
    *   第 $t$ 层的结点有 $2^{t-1}$ 个，要比较 $t$ 次。
    *   ==只考虑查找成功情况下的ASL：$ASL = \log_2(n + 1) - 1 \approx \log_2 n - 1$。
    *   ==综合成功与非成功情况下的ASL：$ASL = \log_2 n + 1/2$。

### ==ASL推导==：把数组变成“一棵满二叉树”

为了方便推导计算，PPT 引入了一个理想状态：假设我们的元素个数 n 正好能够凑成一棵**满二叉树**（每层全满）。

- 设树的层数（深度）为 t。
    
- 总结点个数 n = $2^t - 1$ （比如 t=3 层，就有 7 个节点）。
    
- 反过来推算，层数 $t = \log_2(n + 1)$。
    

在这棵树中：

1. **节点在第 $i$ 层，就说明找到它需要比较 i 次**。（比如根节点在第 1 层，比较 1 次就能找到）。
    
2. **第 i 层一共有 $2^{i-1}$ 个节点**。
    

记住了这棵树，所有的推导就是简单的加减乘除。

### 第一部分：只考虑“查找成功”的情况 (Slide 1)

**1. 逻辑梳理：** 平均查找长度 = **(把树上所有节点都找一遍的总比较次数) / (节点总数 n)**

**2. 分子（总比较次数）怎么算？** 把每一层的比较次数加起来：

- 第 1 层有 $2^0$个节点，每个比较 1 次：$1 \times 2^0$
    
- 第 2 层有 $2^1$ 个节点，每个比较 2 次：$2 \times 2^1$
    
- ...
    
- 第 i 层有 $2^{i-1}$ 个节点，每个比较 i 次：$i \times 2^{i-1}$
    

所以，总比较次数 S 也就是 PPT 里的那个求和符号：

$$S = \sum_{i=1}^{t} (i \times 2^{i-1})$$
**

### 第二部分：考虑“成功 + 失败”的综合情况 

**1. 逻辑梳理：**==平均查找长度 = **(成功的总比较次数 + 失败的总比较次数) / (总的查找情况数量)**

**2. 核心概念：“失败”去哪了？** 看 PPT 里 t=3 的那个例子（数字14,18...那个数组），树的最底层下面还有方形的节点（0~7）。这些方形的空隙，代表的就是**查找失败**掉落的位置。

- n 个真实节点，把数组切出了 n+1 个空隙。所以**失败的情况有 n+1 种**。
    
- 总的查找情况 = 成功的情况(n) + 失败的情况(n+1) = **2n + 1 种**。
    

**3. 失败的总比较次数怎么算？** 在满二叉树中，要想确认查找失败，你必须一直走到树的最底端，然后再往下走一步发现是空的。也就是必须比较 t 次（即树的层数）。

- 失败情况有 n+1 种，每种都要比较 t 次。
    
- **失败总比较次数 = $t \times (n+1)$
    

**4. 组装最终公式：**

$$ASL_{总} = \frac{\sum (i \times 2^{i-1}) + t \times (n+1)}{2n + 1}$$`

分子前面那一半就是我们刚才用错位相减法算出来的成功总次数。

## 六、 插值查找 (Interpolation Search)

### 1. 理论精讲
*   **生活常识**：查英文字典找 "Zebra"，你会从中间翻吗？肯定不会，你直接翻到字典最后面去了。这就是插值查找的灵感。
*   **适用条件**：数据分布比较**均匀**的有序表。
*   **核心公式**：不取1/2处，而是按比例取点：
    $$next = low + \left\lfloor \frac{x - a[low]}{a[high] - a[low]} \times (high - low + 1) \right\rfloor$$
*   **缺点**：每次计算位置包含乘法和除法，计算比较复杂；如果数据分布严重不均（比如一会儿密一会儿疏），性能反而很差。

## 七、 分块查找 (索引顺序块的查找)

### 1. 理论精讲
介于顺序查找和二分查找之间的一种折中方案。
*   **规则**：**块间有序，块内无序（或有序）**。
    也就是第二块里的所有元素，必须都大于第一块里的最大元素。
*   **数据结构**：需要一个**索引表**。索引表里存两样东西：【该块的最大关键字】和【该块在原数组的起始地址】。
*   **两个阶段**：
    1.  **查找索引表**：因为索引表是有序的，可以用折半查找或顺序查找，定位你要找的元素落在哪个块里。
    2.  **查找块**：到对应的块里面去，老老实实地用顺序查找扫描。

### 【练习题二】 动态调整频率的线性表优化
**题意**：用顺序查找单链表。为了让经常查的数据以后查得更快，每次查找到元素后，把这个元素和它的**前驱元素**交换位置（这样经常查的元素就像冒泡一样慢慢升到了链表前端）。

**导师辅导思路**：
在单链表中交换两个节点（或者直接交换它们的数据域）。寻找时，我们需要三个指针：`p`（当前结点），`pre`（前驱结点），`pre_pre`（前驱的前驱，用来保证链表不断）。

**👨‍💻 上机训练（终极Boss战）**：
编写带头结点的单链表，实现该策略：
```cpp
// 核心逻辑提示：
Node* searchAndMove(Node* head, int target) {
    if (!head || !head->next) return nullptr;
    Node* pre_pre = nullptr;
    Node* pre = head;       // 头结点
    Node* p = head->next;   // 第一个真实结点
    
    while (p) {
        if (p->data == target) {
            if (pre == head) return p; // 已经在最前面了，不用换
            
            // 执行指针交换操作（注意不要断链）
            pre_pre->next = p;
            pre->next = p->next;
            p->next = pre;
            
            return p;
        }
        pre_pre = pre;
        pre = p;
        p = p->next;
    }
    return nullptr;
}
```
**测试验证**：按序存入 `1, 2, 3, 4, 5`。连续3次查找数字 `4`。打印每次查找后的链表状态，观察 `4` 是如何一步步“爬”到第一位（头节点之后）的！
