## 第二章：OS 调度器的宠儿 —— 环形队列（Ring Buffer）

为了在绝对有限的连续物理内存中实现无限吞吐，必须将内存“首尾相连”。

### 1. 物理并发悖论：如何区分“队空”与“队满”？

- **方案 A（维护 size 变量）—— 坚决弃用**：多线程高并发下，生产者和消费者疯狂争抢同一个 `size` 变量，引发==**缓存行乒乓（Cache Line Ping-Pong）**==，彻底拖垮 MESI 协议和 CPU 流水线。
    
- ==**方案 B（牺牲一个物理坑位）—— 工业级标配**：==
    
    - **队空**：`front == rear`
        
    - **队满**：`(rear + 1) 回绕 == front`
        
    - **物理优势**：生产者只写 `rear`，消费者只写 `front`，完美实现读写分离与无锁并发（Lock-Free）。
        

### 2. ==性能军规：干掉取模（`%`）运算==

^b61924

- **规则**：强制规定队列的物理容量（Capacity）必须是 **2 的幂次方**。
    
- **位运算黑魔法**：用极其廉价的按位与 `&` 代替极其昂贵的除法器 `%`。
    
- **核心掩码（Mask）**：`mask = Capacity - 1`
    
- **指针推进公式**：`rear = (rear + 1) & mask`（瞬间回绕，只需 1 个 CPU 周期）。

## 第三章：动态扩容与底层类型真理

### 1. 扩容的“腰斩惨案”与“物理展平”

- **禁忌**：环形队列发生扩容时，**绝对不能**像普通栈那样直接 `memcpy` 或无脑循环拷贝。这会将处于回绕状态的“毛毛虫”直接从物理中间斩断。
    
- **物理展平（Unroll）**：必须顺着旧数组的 `front`，配合掩码，一步步将元素按逻辑顺序依次拷贝到新数组的 `0, 1, 2...` 号坑位。
    

### 2. ==位涂抹（Bit Smearing）==

- **场景**：为了保证扩容后的容量永远是 2 的幂次方。
    
- **手法**：找到当前数字最高位的 `1`，通过 `n |= n >> 1`、`>> 2`、`>> 4` 等连招，像抹奶油一样向右铺满，最后 `+1`。
    

### 3.==C++ 底层类型军规==

- **`uint32_t` (无符号 32 位整型)**：跨平台的绝对物理标尺，死死占据 4 个字节。**凡是涉及位运算（`&`、`>>` 等），必须使用无符号类型**，以防止带符号数触发恶心的“算术右移（补 1）”污染掩码。
    
- **`size_t` (内存的绝对标尺)**：它是当前 CPU 架构下最大的无符号整数。在 64 位系统上是 8 字节。**凡是表示数组大小、容量、内存索引的变量，一律使用 `size_t`**，彻底杜绝负数越界。
    
- **32 位与 4GB 的物理绝境**：32 位系统的“32位”本质是指 CPU 只有 32 根地址总线引脚，最高只能组合出 $2^{32}$ 个字节的寻址空间，因此物理内存的极限被死死锁在 **4GB**。

## 第四章：架构级应用与现代 C++ 性能核武

### 1. 离散事件模拟（Simulator）的物理建模

- **核心思想**：不使用 `sleep()` 傻等。使用队列折叠并快进“物理时间”。
    
- **时间跃迁引擎**：每一次出队，对比当前时间（`currentTime`）与事件发生时间（`arrivalTime`）：
    
    - **柜台闲置**：时间断层，`currentTime = arrivalTime + serviceTime`。
        
    - **大排长龙**：时间挤压，`currentTime += serviceTime`，顾客等待时间为 `currentTime - arrivalTime`。
        

### 2. 内存对齐（Memory Alignment）

- **物理起因**：CPU 只能从能被自身位宽整除的物理边界开始读取内存（如 4 字节或 8 字节对齐）。
    
- **Padding 灾难**：为了凑齐边界，编译器会在结构体中间塞入大量无用的垃圾字节，浪费珍贵的 Cache 空间。
    
- **防守阵型**：手写 `struct` 时，**永远将成员变量按 `sizeof` 的大小，==从大到小==依次降序排列**，将物理碎片压缩到极致。
    

### 3. `std::move` 的暴力美学（所有权劫持）

- **本质**：不搬运任何真实数据。它在编译期将左值强转为右值引用，触发类的**移动构造函数**。
    
- **物理效果**：将极其昂贵的深拷贝（例如几百 MB 内存），降维成一次 8 字节的物理指针交接，并冷酷地掏空原对象的指针（置为 `nullptr`）。
    
- **使用军规**：
    
    1. 对 `int` 等不包含堆内存指针的基本类型无效（==直接退化为拷贝==）。
        
    2. 被 `move` 之后的变量，物理上已成空壳，**绝对禁止再次读取**。
